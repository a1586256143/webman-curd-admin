# 命令行工具

插件自带的几条命令，覆盖「生成 CURD」「追加操作按钮 / Excel 导入」「密钥管理」「安装 / 升级 / 迁移」。
**单一职责**：`make:curd` 只生成页面骨架（模型 + 控制器），操作按钮和 Excel 导入拆成独立的
`make:curd-action` / `make:curd-import`，需要时再对已生成的控制器追加，不再用一个命令堆一堆参数。

**统一约定**：都在**宿主根目录**下执行；带 `webman` 前缀的走 webman console（需要宿主装了 `webman/console`），
带 `plugin/curd/...` 的是**脱离框架的独立脚本**（纯 PHP，不依赖 webman，CI / 无 console 时用）。

---

## 1. `make:curd` —— 按表结构生成后台 CURD 骨架

根据数据库表结构一键生成「模型 + 控制器」，列表 / 搜索 / 表单全自动，标题统一走 `__()` 翻译。
**本命令只负责页面骨架**，不生成操作按钮 / 导入（那些见 §2 / §3）。

```bash
# 最简：表名必填，其余自动推导
php webman make:curd --table=my_test

# 指定标题并自动注册路由（写入 config/admin-route.php，写前备份 .bak）
php webman make:curd -t my_test --title=测试管理 --register

# 指定数据库连接 + 覆盖已存在文件
php webman make:curd -t hf_goods -d mysql_business -f
```

### 完整选项

| 选项 | 简写 | 说明 |
|---|---|---|
| `--table` | `-t` | **必填**，数据库表名，如 `my_test` |
| `--name` | `-c` | 控制器类名，默认由表名推导（`my_test` → `MyTestController`） |
| `--model` | `-m` | 模型类名，默认推导（`my_test` → `MyTest`） |
| `--route` | `-r` | 前端路由路径，默认 `/表名`（`my_test` → `/my-test`） |
| `--title` | — | 页面标题，默认取表注释（无注释用字段推导的英文短语，走 `__()`） |
| `--controller-path` | `-C` | 控制器目录，默认 `app/controller/admin/api` |
| `--model-path` | `-M` | 模型目录，默认 `app/model` |
| `--connection` | `-d` | 数据库连接名，默认取插件配置 `business_connection` |
| `--register` | — | 自动把路由写进 `config/admin-route.php`（没有则新建），写前备份 `.bak` 并 `php -l` 自检 |
| `--no-model` | — | 只生成控制器，不生成模型 |
| `--force` | `-f` | 同名文件已存在时覆盖（默认跳过并提示） |

> 不传 `--table` 时进入交互询问；`--table` 指定的表不存在会直接报错。
> 生成后想加操作按钮 / Excel 导入 → 用 §2 `make:curd-action` / §3 `make:curd-import`。

### 生成了什么

- **模型** `{app/model}/{Model}.php`：表有 `deleted_at` 自动 `use SoftDeletes`，有 `created_at/updated_at` 自动维护；基类优先用宿主 `app/model/BaseModel`，没有则回退插件内置版。
- **控制器** `{app/controller/admin/api}/{Model}Controller.php`：继承 `BaseCurdController`——
  列表列 = 表字段全量、搜索项 = 前几个 varchar 走 `like` / enum 走 `select`、表单 = 按字段类型映射控件；
  **不声明 `$modelClass`**（框架从 Grid 自动提取）、**Grid 不传 title**（自动读控制器 `title()`）。
- **路由**：默认**不进** `curd_configs` 配置表，只在宿主路由文件注册路径（见下），改 `grid()` 即时生效、不被落库配置覆盖。

### 命名推导（`my_test` → `/my-test`）

| 表名 | 模型 | 控制器 | 路由 |
|---|---|---|---|
| `my_test` | `MyTest` | `MyTestController` | `/my-test` |
| `a_packages` | `APackage` | `APackageController` | `/packages` |
| `admin_users` | `AdminUser` | `AdminUserController` | `/admin-users` |

### 路由注册写到哪

`--register` 的目标优先级：`config/admin-route.php`（标准，插件自动加载）→ 项目根 `admin-route.php`（旧位置）→ `config/route.php`。
没加 `--register` 时，命令末尾会打印一段 `RouteControllerRegistry::registerMany([...])` 让你手动贴。
**改完路由必须 `php webman restart`**（reload 不重新加载路由）。

## 2. `make:curd-action` —— 给已生成的控制器追加操作按钮

在**已生成**的 CURD 控制器上追加「行级操作」或「批量操作」按钮（不在 `make:curd` 阶段生成，
按需单独追加）。命令做两件事（幂等：方法已存在则跳过，加 `--force` 重写）：

1. 在 `grid()` 里插入 `$grid->action(...)`（行级）或 `$grid->batAction(...)`（批量）声明；
2. 在类末尾追加 `public function action{Name}(Request $request)` 方法骨架。

写入前备份 `.bak`，写入后 `php -l` 自检，失败自动回滚。

```bash
# 行级按钮：操作名 audit，按钮标题「审核」
php webman make:curd-action -t hf_goods --name=audit:审核

# 批量按钮（勾选行后可用，请求带 ids）
php webman make:curd-action -t hf_goods --name=batch-on:批量上架 --batch

# 控制器不在默认目录 / 已知类名时，直接用 --controller 指定（短名或 FQCN）
php webman make:curd-action -c HfGoodsController --name=audit:审核
```

### 完整选项

| 选项 | 简写 | 说明 |
|---|---|---|
| `--table` | `-t` | 表名，用于定位控制器（与 `--controller` 二选一，默认目录 `app/controller/admin/api`） |
| `--controller` | `-c` | 控制器类名（短名或 FQCN），优先于 `--table` |
| `--name` | — | **必填**，操作名 `[:按钮标题]`，如 `audit:审核`（`name` 不能含空格） |
| `--batch` | — | 生成**批量**操作（勾选行后可用，请求带 `ids`） |
| `--force` | `-f` | 方法已存在时也重新写入（默认跳过并提示） |

### 生成了什么

- **grid() 里插入一行**：
  - 行级：`$grid->action('audit', '审核')->icon('Edit')->confirm('确定执行「审核」吗？')->handler('audit');`
  - 批量：`$grid->batAction('batch-on', '批量上架')->confirm('确定执行「批量上架」吗？')->handler('batch-on');`
  - 两者都走控制器方法（`handler('xxx')` 表示交给 `actionXxx()`），不生成 Action 子类。
- **类末尾追加方法骨架**：
  - 行级 `actionAudit(Request $request)`：取 `$request->post('id')`；
  - 批量 `actionBatchOn(Request $request)`：取 `$request->post('ids')` 数组并 `intval` 过滤。

按钮名 `batch-on` 会推导成方法名 `actionBatchOn`（`-` / `_` 后字母大写）。打开控制器在骨架里补业务逻辑即可；
改完 PHP 类务必 `php webman restart`，刷新后台页面按钮即出现。

## 3. `make:curd-import` —— 给已生成的控制器追加 Excel 导入

在**已生成**的 CURD 控制器上追加「Excel 导入」按钮（不在 `make:curd` 阶段生成，按需单独追加）。命令做两件事（幂等：方法已存在则跳过，加 `--force` 重写）：

1. 在 `grid()` 里插入 `$grid->importAction(...)` 声明（工具栏按钮 + 文件弹窗）；
2. 在类末尾追加 `public function actionImport(Request $request)` 方法骨架（内部 `$this->excelRows('file')` 逐行处理）。

写入前备份 `.bak`，写入后 `php -l` 自检，失败自动回滚。

```bash
# 默认：操作名 import / 标题「导入」
php webman make:curd-import -t hf_goods

# 自定义操作名与标题
php webman make:curd-import -t hf_goods --name=import-goods:导入商品

# 已知类名时直接用 --controller 指定
php webman make:curd-import -c HfGoodsController
```

### 完整选项

| 选项 | 简写 | 说明 |
|---|---|---|
| `--table` | `-t` | 表名，用于定位控制器（与 `--controller` 二选一，默认目录 `app/controller/admin/api`） |
| `--controller` | `-c` | 控制器类名（短名或 FQCN），优先于 `--table` |
| `--name` | — | 导入操作名 `[:按钮标题]`，默认 `import:导入` |
| `--force` | `-f` | 方法已存在时也重新写入（默认跳过并提示） |

### 生成了什么

- **grid() 里插入一行**：`$grid->importAction('import', '导入');`（工具栏按钮 + 文件选择弹窗）。
- **类末尾追加方法骨架** `actionImport(Request $request)`：
  - `$rows = $this->excelRows('file');` 返回 `[{表头 => 值}, ...]`（首行为表头，列名与字段标签一致）；
  - 已含「逐行落库 + 成功 / 失败计数」的 TODO 骨架，补业务即可。

Excel 约定：首行为表头，列名需与字段标签一致（否则 `excelRows` 读不到对应键）；改完 PHP 类务必 `php webman restart`。

## 4. `curd:crypto-key` —— 接口加密密钥

查看 / 生成 / 更换 RSA 密钥对（与 [接口加密](14-接口加密与异常兜底.md) 配套）。正常安装**不需要手动跑**——
`install.php` / Web 安装向导 / 升级都会自动生成；本命令用于密钥丢失、换机迁移、主动换钥。

```bash
php webman curd:crypto-key                 # 生成（已存在则跳过；只有私钥时只补公钥）
php webman curd:crypto-key --show          # 只看状态与公钥指纹，不生成
php webman curd:crypto-key --force         # 换一对新的（旧密文将无法解密）
php webman curd:crypto-key --bits=4096     # 指定位数
php webman curd:crypto-key --print-public  # 额外打印公钥 PEM
```

| 选项 | 简写 | 说明 |
|---|---|---|
| `--force` | `-f` | 强制重新生成一对（旧密文将无法解密） |
| `--bits` | — | RSA 位数，默认 `2048`（建议 `2048` / `4096`） |
| `--show` | `-s` | 只显示状态与指纹，不生成 |
| `--print-public` | — | 额外打印公钥 PEM（要内嵌进前端时用） |

> 换密钥后**务必 `php webman restart`**：私钥在进程内存里，不重启就还是旧的（会 400 / key-mismatch）。
> 前端不用重新打包 —— 发行产物是 `auto` 模式，启动时自动握手拿新公钥。

## 5. 独立脚本（不依赖 webman / console）

CI、Docker、或宿主没装 `webman/console` 时直接用 `php` 跑，效果与上面几条等价。

### 5.1 `plugin/curd/keygen.php` —— 生成密钥（纯 openssl）

```bash
php plugin/curd/keygen.php            # 生成
php plugin/curd/keygen.php --show     # 只看状态与指纹
php plugin/curd/keygen.php --force    # 换一对新的
php plugin/curd/keygen.php --bits=4096
```

与 `curd:crypto-key` 共用 `app/CryptoKeys.php`，区别只是：本脚本脱离框架（读不到宿主 `config`，密钥目录取默认路径）。

### 5.2 `plugin/curd/install.php` —— 一键安装（建表 / 种子 / 密钥）

```bash
php plugin/curd/install.php
php plugin/curd/install.php --admin-user=admin --admin-pass='你的密码'   # 自定义初始管理员
php plugin/curd/install.php --business-sql=install-business.sql          # 自带业务表 SQL（可重复 / 逗号分隔）
php plugin/curd/install.php --business-connection=mysql_business         # 临时覆盖业务连接名
php plugin/curd/install.php --progress-file=runtime/curd-installer.log   # 进度 JSONL（Web 向导内部用）
```

等价于 `Install::install()`，但先完成配置加载（`vendor/autoload.php` → `.env` → `App::loadAllConfig`），不启动 worker、不注册路由。
**幂等**：表用 `CREATE TABLE IF NOT EXISTS`，种子按「表空才插」，重复执行全部 SKIP。

### 5.3 `plugin/curd/migrate.php` —— 增量迁移

```bash
php plugin/curd/migrate.php            # 执行 migrations/V{n}__*.sql 中尚未应用的迁移
```

用于插件升级时追加的表结构变更（区别于 install 的全量建表 + 种子）。

## 6. webman 内置进程命令（顺带一提）

这些不是插件的，但天天要用：

```bash
php webman start -d        # 后台启动（推荐；不要前台 restart，会卡住不返回）
php webman restart         # 重启（改 PHP 代码 / 配置 / 路由后必须）
php webman reload          # 平滑重载（仅 config 等常驻不缓存的项；路由 / 类文件改了不生效）
php webman stop            # 停止
```

> 改了 **PHP 类 / 路由 / config** 都要 `restart`；只改 `.env` 可用 `reload`（`SIGUSR1`）。

## 7. 怎么确认命令装好了

```bash
# 列出所有可用命令（这五条应在列）
php webman

# 看到 make:curd / make:curd-action / make:curd-import / curd:crypto-key / curd:publish-skill 即正常；
# 没有说明宿主没装 webman/console
```

- `make:curd` / `make:curd-action` / `make:curd-import` / `curd:crypto-key` / `curd:publish-skill` 由插件 `config/app.php` 的 `'command'` 显式注册（免疫软链），装好插件即生效。
- `keygen.php` / `install.php` / `migrate.php` 是**文件**，直接用 `php` 调用，无需任何注册。

## 8. `curd:publish-skill` —— 把 AI 开发技能发布到宿主项目根

本插件是 composer 包：技能随包落在 `plugin/curd/skills/`（以及 vendor 包体里），而 AI 工具只扫
**工作区根目录**（WorkBuddy 看 `.workbuddy-ai/skills/`，Cursor / Codex 看 `AGENTS.md`），所以默认**扫不到**。
本命令把技能复制到项目根，并维护 `AGENTS.md` 托管块：

```bash
php webman curd:publish-skill            # 发布技能 + 写入/更新 AGENTS.md（幂等）
php webman curd:publish-skill --force    # 覆盖已有技能文件（升级插件后同步最新手册）
php webman curd:publish-skill --no-agents# 只发布技能，不动 AGENTS.md
php webman curd:publish-skill --dry-run  # 只看会做什么，不落盘
```

| 选项 | 简写 | 说明 |
|---|---|---|
| `--force` | `-f` | 覆盖宿主已存在的技能文件（默认跳过） |
| `--no-agents` | — | 只发布技能目录，不写/更新宿主根 `AGENTS.md` |
| `--dry-run` | — | 只打印将要做什么，不落盘 |

**做了什么**：
- 复制 `plugin/curd/skills/webman-curd-admin-dev/SKILL.md` →
  `{项目根}/.workbuddy-ai/skills/webman-curd-admin-dev/SKILL.md`；
- 在 `{项目根}/AGENTS.md` 写入/替换一段带
  `<!-- webman-curd-admin:skill:begin/end -->` 标记的托管块（保留文件其余内容，幂等）。

之后用 AI 工具打开项目根即可扫到；升级插件后加 `--force` 重跑一次同步最新手册。
