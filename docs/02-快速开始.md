## 2. 五步建一个 CURD 页

以「套餐管理」（表 `a_package`）为例：两个 PHP 文件 + 一处路由 + 一步后台操作。

### 2.1 ① 模型：`app/model/APackage.php`

启动时自动扫描进 `ModelRegistry`，不用手写注册：

```php
<?php
namespace app\model;

use plugin\curd\app\model\BaseModel;

class APackage extends BaseModel
{
    protected $table = 'a_package';
}
```

### 2.2 ② 控制器：`app/controller/api/PackageController.php`

继承插件基类即获得整套列表 / 搜索 / 表单 / 增删改查 / 导出能力：

```php
<?php
namespace app\controller\api;

use app\model\APackage;
use plugin\curd\app\controller\base\BaseCurdController;
use plugin\curd\app\dsl\Filter;
use plugin\curd\app\dsl\Form;
use plugin\curd\app\dsl\Grid;

class PackageController extends BaseCurdController
{
    // 标题只写这一处：Grid 不传第二个参数时自动读它
    protected string $title = '套餐管理';

    private const STATUS = [0 => '停售', 1 => '在售'];

    protected function grid(): Grid
    {
        // ① 模型直接 new 进 Grid —— 框架自动回填 $modelClass，不必再声明该属性
        $grid = new Grid(new APackage());
        $grid->getModel()->orderByDesc('id');

        // ② 列
        $grid->column('id', __('ID'))->width(80)->align('center');
        $grid->column('name', __('Name'))->minWidth(160)->sortable();
        $grid->column('price', __('Price'))->prefix('¥ ')->width(120);
        $grid->column('status', __('Status'))->map(self::STATUS)->label([1 => 'success'])->width(100);
        $grid->column('created_at', __('Created at'))->datetime()->width(180);

        // ③ 搜索
        $grid->filter(function (Filter $filter) {
            $filter->like('name', __('Name'));
            $filter->select('status', __('Status'))->options(self::STATUS);
        });

        // ④ 新增 / 编辑表单
        $grid->form(function (Form $form) {
            $form->text('name', __('Name'))->required();
            $form->number('price', __('Price'))->required()->min(0);
            $form->radio('status', __('Status'), self::STATUS)->default(1);
        });

        return $grid;
    }
}
```

`$modelClass` 不用声明（框架从 `grid()` 里列的模型自动提取回填）；手动写也兼容。
`grid()` 里用到 `request()` 等请求上下文的控制器，建议保留显式声明 —— 启动扫描期不执行 `grid()`。

### 2.3 ③ 路由：`config/admin-route.php` 或 `config/route.php`

```php
use plugin\curd\app\RouteControllerRegistry;

RouteControllerRegistry::registerMany([
    '/package' => \app\controller\api\PackageController::class,
]);

// 单条也行：
// RouteControllerRegistry::register('/package', \app\controller\api\PackageController::class);
```

放哪个文件都行：`config/admin-route.php`（推荐，后台路由集中管理，插件自动加载；注意写在
`return ['register' => function () { ... }]` 闭包里）或 `config/route.php`（老项目照旧）。
区别见 [§6.1](#61-后台路由单独放-configadmin-routephp)。

这样注册的页面**不进 `curd_configs` 落库配置**，改 `grid()` 立即生效（registry 优先于落库配置）。

### 2.4 ④ 重启

```bash
php start.php restart
```

### 2.5 ⑤ 后台登记菜单 + 授权

「菜单管理」新增一条：`path` 填 **`/package`**（与 ③ 一致），`permission` 可留空由「一键生成权限」推导。
再到「角色管理」给对应角色勾上该菜单。刷新后台 → 左侧出现「套餐管理」，增删改查 / 导出全部可用。

> 完整 `grid()` 能力见 [DSL · CURD 页面](11-DSL-CURD页面.md)，逐个方法查 [API · Grid](20-API-Grid.md)。

## 3. 页面访问路径怎么定

菜单的 `path` 就是页面 URL：

| 页面类型 | 路径形态 | 谁生成 |
|---|---|---|
| CURD 页 | `/package`、`/mobile-recharge-orders` —— 即 `registerMany` 的 key | 你在 `config/route.php` 定 |
| Schema / `.vue` 自定义页 | `/custom-page/<页面名>` | 前端 catch-all 命中，`PageRegistry` 注册内容 |

## 4. 后台「配置生成器」（不写代码）

`/app/curd/curd-generator` 是内置可视化工具页（它自己不需要 DSL 配置）：

1. 选表 → 自动读字段；
2. 勾列 / 搜索项 / 表单项，改标题、控件类型；
3. 填页面路径（如 `/package`）与标题；
4. 保存 —— 写入 `curd_configs`，`/api/curd/config` 立刻能查到该 `route_path`；
5. 到「菜单管理」加菜单（path 填同一路径）并授权。

**代价**：配置落库后想再用代码精调（自定义 action、`display` 闭包、`setCustomJs`）就得回到控制器写法 ——
落库配置不读你的 `grid()`。选择标准：**长期维护 / 要写逻辑 → 控制器**；**一次性工具页 → 生成器**。

> **生产环境默认关闭**：`generator_enabled` 未配置时跟随调试模式（`APP_DEBUG=false` → 关闭）。
> 关闭后菜单隐藏、直连 `/curd-generator` 被拦回首页、后端 5 个生成器接口返回 403。
> 详见 [配置参考 §generator_enabled](03-配置参考.md)。

## 5. 开箱示例「测试管理」

装包时示例文件已自动落位宿主根（`src/Install.php` 的 `ensureExamples`），启用两步：

```php
// a) 宿主 config/route.php 注册（MyTestController.php 头注释含完整写法）
RouteControllerRegistry::registerMany([
    '/my-test' => \app\controller\admin\api\MyTestController::class,
]);
// b) 安装时已种好：my_test 表 + curd_configs 的 /my-test 配置 +「测试管理」菜单
```

- **全新项目**：安装向导自动建表 + 补菜单 + 插 1 条示例数据；
- **已运行项目**：跑一次 `php plugin/curd/install.php`（幂等）补齐表与菜单；
- **删除**：控制器 + `app/model/MyTest.php` + `bootstrap.php` 的「内置示例」注册段 +
  `menus` 里的「测试管理」行 + `my_test` 表（控制器头注释含完整清单）。

这个示例既是**链路自检**（登录 → 菜单 → 配置接口 → 数据接口 → 库表全通），也是**能力样板**：
`display()` 渲染 HTML、`help()` 里写 `@click`、`setCustomJs()` 定义函数、点式字段读写 JSON 列、
`copy()` / `select()` 行内编辑，全在这一个文件里。

## 6. 命令行生成 `make:curd`

按**数据库表结构**生成 Grid + Form（字段、控件类型、标题全自动），可选顺带生成操作按钮。
**装好即可用**，宿主不用改任何配置（插件在 `config/app.php` 里显式注册了命令，
`plugin/curd` 用软链挂载也能识别；命令消失见 [FAQ §10](16-排错速查与FAQ.md)）。

```bash
# 最简：按表名生成（模型 + 控制器）
php webman make:curd -t my_test

# 指定数据库连接（表不在默认业务库时）
php webman make:curd -t request_sms -d mysql_business

# 常用：指定类名 / 标题 / 路由，并自动写进宿主路由文件
php webman make:curd -t hf_goods -c HfGoods -m HfGoods --title='商品管理' -r /hf-goods --register

# 带操作按钮：行级审核 + 批量上架 + Excel 导入
php webman make:curd -t hf_goods --title='商品管理' \
  --action=audit:审核 --bat-action=batch-on:批量上架 --import-action
```

| 选项 | 说明 |
|---|---|
| `-t --table` | 表名（必填），字段 / 类型 / 注释由 `SHOW FULL COLUMNS` 读取 |
| `-d --connection` | **数据库连接名**，取 `config/database.php` 的 `connections` 键（如 `mysql_business`）；默认取插件配置 `business_connection`（单库时就是主库） |
| `-c --name` / `-m --model` | 控制器 / 模型类名，默认由表名推导（`my_test` → `MyTest`） |
| `-r --route` | 前端路由路径，默认 `/表名`（下划线→中划线） |
| `--title` | 页面标题，默认取表注释 |
| `--action` | 行级操作，`name[:按钮标题]`，**可重复**；同时生成控制器 `action{Name}()` 骨架 |
| `--bat-action` | 批量操作（勾选行后可用），`name[:按钮标题]`，**可重复**；生成 `action{Name}()` 骨架 |
| `--import-action` | Excel 导入按钮，`name[:按钮标题]`；不写值 = `import:导入`；生成 `actionImport()` 骨架 |
| `--register` | 自动把 `RouteControllerRegistry::registerMany([...])` 写进 **`config/admin-route.php`**（不存在会按模板新建；其次旧位置项目根 `admin-route.php`，都没有才写 `config/route.php`）；先备份 `.bak`，写入后 `php -l` 自检 |
| `-C` | 控制器目录，默认 `app/controller/admin/api` |
| `-M` | 模型目录，默认 `app/model` |
| `--no-model` | 只生成控制器，不生成模型 |
| `-f --force` | 同名文件已存在时覆盖（默认跳过） |

> `-d` 只影响**读表结构**（`SHOW FULL COLUMNS`）和生成的模型 `$connection`；
> 表不在默认库里时必须带上，否则报 `Table 'xxx' doesn't exist`。

类型映射：`enum`→下拉、`set`→多选、`tinyint(1)`→开关、`text`→textarea、
`decimal/int`→数字、`date/datetime`→日期，其余 text。

**操作按钮命名推导**（`--action=audit:审核` → `$grid->action('audit','审核')` → 控制器 `actionAudit()`）：

```php
// 生成的按钮配置
$grid->action('audit', '审核')->icon('Check')->confirm('确定审核该记录？')->handler('audit');
$grid->batAction('batch-on', '批量上架');                    // = action()->batch(true)
$grid->importAction();                                       // = action('import','导入')->global(true) + excel 表单

// 生成的控制器方法骨架
public function actionAudit(Request $request)  { /* 单行：$request->post('id') */ }
public function actionBatchOn(Request $request) { /* 批量：$request->post('ids') */ }
public function actionImport(Request $request) { /* Excel：$this->excelRows('file') */ }
```

按钮名 `batch-on` 会转成方法名 `actionBatchOn`（`-` / `_` 后字母大写）。

生成物约定：

- **字段标题统一 `__()`，key 用「字段名推导的英文短语」**：`request_order` → `__('Request order')`、
  `created_at` → `__('Created at')`。**数据库里的中文注释不会当 key**，只作为生成后给出的翻译建议
  （`'Request order' => '请求订单号',`）。
  未命中翻译时原样显示英文 —— 想显示中文就往 `resource/translations/zh_CN/fields.php` 补，
  生成结束会列出「还没登记的 key → 中文注释」对照表。
- **页面标题**：`--title` 优先，其次表注释，都没有才用表名推导。
- **不声明 `$modelClass`**（框架自动从 Grid 的模型提取回填）；**Grid 不传 title**（自动读 `title()` 方法）；
- **不进 `curd_configs`**：只在宿主路由文件注册 —— 改 `grid()` 立即生效。
- **`created_at` / `updated_at` 列表列不加 `->datetime()`**：按原值展示（需要格式化自己补 `->datetime()` 或 `display()`）；
  `updated_at` / `deleted_at` 默认 `->hidden()`，`created_at` 可见。

生成后收尾：`--register` 已写好路由（否则手抄命令输出那一行）→ 后台「菜单管理」加菜单并授权。

### 6.1 后台路由单独放 `config/admin-route.php`

后台页面越来越多时，`config/route.php` 会混着「项目自身接口」和「后台 CURD 页面」。可以拆开：

| 文件 | 放什么 |
|---|---|
| **`config/admin-route.php`** | 后台页面路由（`RouteControllerRegistry`）+ 后台专用 `Route::group` |
| `config/route.php` | 项目自身的接口 / 前台路由 |

```php
// config/admin-route.php —— 插件自动加载，config/route.php 里不用加任何一行
use plugin\curd\app\RouteControllerRegistry;
use Webman\Route;

return [
    'register' => function () {
        RouteControllerRegistry::registerMany([
            '/my-test'  => \app\controller\admin\api\MyTestController::class,
            '/hf-goods' => \app\controller\admin\api\HfGoodsController::class,
        ]);

        Route::group('/api/admin', function () {
            Route::get('/stats', [\app\controller\admin\api\AdminStatsController::class, 'index']);
        })->middleware([
            \plugin\curd\app\middleware\CorsMiddleware::class,
            \plugin\curd\app\middleware\AuthCheck::class,
            \plugin\curd\app\middleware\PermissionCheck::class,
        ]);
    },
];
```

> ⚠️ **必须 `return` 数组，路由写在 `register` 闭包里**。webman 启动时会把 `config/` 下除
> `route.php` 以外的所有 `.php` 当**配置**加载（`Config::loadFromDir`，早于路由初始化），此时
> `Route` 还没初始化：顶层直接 `Route::group()` 会报
> `Call to a member function addGroup() on null`；直接 `return function () {}` 又会因为
> `array_replace_recursive()` 只接受数组而报 TypeError。
> 插件在路由加载阶段取出 `config('admin-route.register')` 执行，所以闭包里可以正常写路由。

- **加载顺序**：`config/route.php` → **`config/admin-route.php`（执行闭包）** → `plugin/curd/config/route.php`，
  这里注册的同名路由优先，插件同路径路由会被冲突检测跳过。
- **文件不存在就跳过**：老项目不建这个文件，行为完全不变。
- `make:curd --register` 会自动选目标：优先 `config/admin-route.php`（不存在会按模板新建），
  其次旧位置（项目根 `admin-route.php`），都没有才写 `config/route.php`。
- 升级插件后想启用：重跑安装器会生成模板，或手动新建。
- 改完路由要 `php webman restart`（`reload` 不重新加载路由）。

> **兼容旧位置**：早期版本要求放**项目根目录** `admin-route.php`（顶层直接写 `Route::xxx()`）。
> 插件仍支持：仅当 `config/admin-route.php` 不存在时才 `require` 根目录那份。新项目请用 `config/`。

## 7. 业务库表结构 · 种子 · 增量 migration

### 7.1 业务建表 SQL

`install.sql` 默认只建认证 / 管理面那 8 张表。项目专有业务表由项目自带：放 `install-business.sql`
到项目根，语句间用 `--SPLIT--` 分隔，`CREATE TABLE IF NOT EXISTS` 保证幂等（此文件**不**打包进通用包）。

```bash
php plugin/curd/install.php --business-sql=install-business.sql

# 多个文件（可重复或逗号分隔）
php plugin/curd/install.php --business-sql=sql/admin.sql --business-sql=sql/business.sql

# 临时切换业务库连接（默认 business_connection，即 mysql_business）
php plugin/curd/install.php --business-sql=install-business.sql --business-connection=mysql_business_test
```

### 7.2 业务种子（菜单 / 权限自动登记）

把菜单 / 权限种子追加到业务 SQL 里，全用 `INSERT IGNORE` 保持幂等：

```sql
-- install-business.sql
-- 菜单：path 必须与 RouteControllerRegistry 注册的路径一致
INSERT IGNORE INTO menus (parent_id, title, icon, path, permission, sort, type, visible)
VALUES (0, '测试管理', 'Monitor', '/my-test', 'curd:MyTest', 90, 1, 1);
--SPLIT--
-- 权限：admin 角色已带 p,admin,*,* 通配，通常只需给其它角色补
INSERT IGNORE INTO casbin_rule (ptype, v0, v1, v2)
VALUES ('p', 'yunying', 'curd:MyTest', '*');
```

| 表 | 关键列 |
|---|---|
| `menus` | `parent_id`（0 = 顶级）、`title`、`icon`（Element Plus 图标名）、`path`、`permission`、`sort`、`type`（1 = 菜单项 / 2 = 子菜单容器）、`visible` |
| `casbin_rule` | `ptype`（`p` = 策略 / `g` = 角色继承）、`v0`（角色）、`v1`（obj）、`v2`（act） |

> `path` 推导权限标识的规则是 `curd.{Model}`；`permission` 留空时由「一键生成权限」推导。
> 详见 [菜单与权限](12-菜单与权限.md)。

### 7.3 增量 migration

```bash
# 文件命名：plugin/curd/migrations/V{版本}__{描述}.sql，版本号升序，--SPLIT-- 分隔多语句
php plugin/curd/migrate.php                       # 跑全部未执行迁移
php plugin/curd/migrate.php --connection=mysql    # 指定连接
php plugin/curd/migrate.php --dry-run             # 预检
```

已执行版本记录进 `{连接库}._curd_migrations`（唯一约束，幂等）；已发布版本**只追加不修改**。

## 8. 配置写在哪个文件

| 内容 | 写在哪 |
|---|---|
| 数据库连接（`DB_*`） | 宿主 `.env`（`config/database.php` 用 `env()` 读取；安装向导自动写） |
| 插件调参 + 站点信息 + 验证码 + 上传 + 导出上限 + 生成器开关 | 宿主根 **`config/curd-admin.php`**（唯一入口） |
| ❌ 不再读取 | `config/curd.php`、`config/admin.php`（2026-09-19 已合并，存在也不生效） |

配置改完**必须重启 webman**（启动期读取）；`site` / `home_page` / `captcha_*` / `generator_enabled`
这几项改完无需重建前端。全部键位与默认值见 [配置参考](03-配置参考.md)。
