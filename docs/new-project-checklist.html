webman-crud 新项目接入流程表

插件：huafei/webman-crud（type: webman-app-plugin） · 适用：webman-framework ^2.1 / PHP ≥8.1 / MySQL 5.7+ · 生成于 2026-09-05，与包 v0.1.0 交付物一致；G1–G9 缺口已全部闭合

P0前置环境检查

✓检查项要求 / 命令说明
☐PHPphp -v ≥ 8.1，含 pdo_mysql / mbstring宿主框架硬性要求
☐Composercomposer -V用于装插件与依赖
☐MySQL≥5.7，utf8mb4；账号具备 CREATE / ALTER 权限认证库 + 业务库（可同实例分库）
☐Node 仅前端定制≥18；沙箱环境用 env -u NODE_OPTIONS npm只在需要重建内置前端时使用
☐插件来源可达私有 Git 仓库 / Satis / 本地 path已闭环：私有 Git(VCS)/Satis/path 三选一（README 安装段）

P1创建项目骨架

✓步骤命令 / 操作产物 / 验收点
☐1.1 初始化 webman 项目
composer create-project workerman/webman-project my-app
cd my-app
标准 webman 骨架（config/ app/ runtime/）
☐1.2 确认端口改 config/server.php listen 端口避免与其它项目冲突
☐1.3 空跑一次php start.php start（前台跑确认无错）欢迎页 200，再 stop

P2引入插件

✓步骤命令 / 操作产物 / 验收点
☐2.1 配置插件源
"repositories": [{
  "type": "vcs",
  "url": "git@your-git:huafei/webman-crud.git"
}]
私有源三选一：VCS / Satis / 本期临时 path："type":"path","url":"/Users/colin/Public/www/company/webman-crud"		composer 能解析到包
☐2.2 安装composer require huafei/webman-crud:@dev钩子自动把 plugin/crud 拷到 {项目}/plugin/crud（support\Plugin::install）
☐2.3 校验拷贝完整ls plugin/crud/{app,config,public,api,install.php,install.sql}关键文件齐全；public/ 含前端 dist（47+ 文件）

P3配置（.env + 连接）

✓配置项示例值说明
☐DB_HOST / DB_PORT / DB_NAME / DB_USER / DB_PASSWORD127.0.0.1 / 3306 / my_admin / …认证库（admin_users / roles / menus / casbin…）
☐CRUD_ADMIN_CONNECTIONmysql认证库连接名（默认 mysql）
☐CRUD_BUSINESS_CONNECTIONmysql_business业务库连接名；用业务库时需在 config/database.php 增加同名连接
☐CRUD_ADMIN_REQUIRE_PERMISSIONtrue（生产）/ false（开发）/api/admin/* 是否走 casbin 鉴权（默认 false 兼容旧行为）
☐CRUD_PAGE_BASE/app/crud前端挂载前缀，改了需同步重建前端（VITE_BASE_PATH）
☐业务库连接config/database.php 加 mysql_business仅业务分库时需要
⚠️ 配置覆盖顺序：webman 先加载 config/ 再加载 plugin/*/config，插件配置会覆盖 config/plugin/crud/crud.php —— 根应用调参只能走 .env（上表全部键均已接 env）。

P4安装（建表 + 种子 + 密钥）

✓模式命令说明
☐基础（8 张认证表）
php plugin/crud/install.php
建 8 表 + 种子（3 角色 / 6 菜单 / admin-admin123 / casbin 超管）+ 生成 RSA-2048 密钥对到 config/keys/
☐含业务表
php plugin/crud/install.php \
  --business-sql=plugin/crud/install-business.sql \
  --business-connection=mysql_business
--business-sql 可重复 / 逗号分隔；相对路径基于项目根。业务 SQL 是项目专有文件（不随包分发），需自备
☐幂等复跑重复执行同命令全部 SKIP，无副作用；失败可直接重试
验收：输出无 [ERROR]；config/keys/api_rsa_{private,public}.pem 已生成；MySQL 中 8（+N 业务）张表存在。

P5启动与验收清单

php start.php start -d
✓#验收项预期
☐1GET /app/crud/200（SPA 首页）
☐2GET /app/crud/dashboard200（history fallback）
☐3GET /app/crud/assets/*.js200（静态资源）
☐4GET /api/auth/me 无 tokenHTTP 200 + 业务码 401（API 约定）
☐5OPTIONS /api/auth/login204（CORS 预检）
☐6POST /api/auth/login admin/admin123返回 token + roles:["admin"]
☐7带 token：/api/admin/users / roles / profile / menus全 200
☐8GET /api/config/site200 站点配置
若开 CRUD_ADMIN_REQUIRE_PERMISSION=true：追加验证——无策略的普通角色访问 /api/admin/users 应 403，casbin 授权后 200。

P6前端（二选一）

✓路线操作说明
☐6A. 直接用内置 dist 默认无操作包内 plugin/crud/public/ 开箱即用，base=/app/crud/、同域 API、关闭传输加密
☐6B. 定制重建
CRUD_FRONTEND_DIR=~/code/crud-frontend \
  ./scripts/build-frontend.sh
脚本按 VITE_BASE_PATH=/app/crud/ 构建 → 回灌 plugin/crud/public/ → 前缀自检。npm 报 Brokered host 错误时用 env -u NODE_OPTIONS npm
☐6B-加密分支 仅 API_ENCRYPT=true把 config/keys/api_rsa_public.pem 替换进前端源码 → 再跑 6B信封加密部署需公钥进前端；默认关闭可跳过

P7业务开发（写控制器即跑）

✓步骤操作说明
☐7.1 建业务表写 plugin/crud/install-business.sql（--SPLIT-- 分隔，全 CREATE TABLE IF NOT EXISTS），重跑 P4 安装命令表结构变更走增量 SQL 文件，靠人维护（见缺口 G5）
☐7.2 建模型app/model/Xxx.php extends plugin\crud\app\model\BaseModelModelRegistry 自动扫描 app/model/；连接/扫描目录走 config('plugin.crud.crud.*')
☐7.3 写控制器
namespace app\controller\api;
use plugin\crud\app\controller\base\BaseCrudController;
class GoodsController extends BaseCrudController {
    protected string $modelClass = \app\model\Goods::class;
    protected string $title = '商品管理';
}
一行继承即得整套 CRUD + 查询 + 权限
☐7.4 注册路由宿主 config/route.php 直接 Route::any(...)插件用 crud_route() 冲突检测、宿主优先，同名路由不会崩
☐7.5 登记菜单/权限后台「菜单管理」加节点 + casbin 规则（或手写 menus / casbin_rule 种子 SQL 追加进 install-business.sql）见缺口 G4：业务菜单目前无自动种子
☐7.6 验证重启 → 前端菜单出现 → CRUD 增删改查跑一遍

P8生产部署

✓项操作说明
☐守护进程supervisor / systemd 托管 php start.php start禁用 -d 裸跑
☐Nginx 反代/ → webman；/app/crud/ 同域透传SPA 与 API 同域，免 CORS
☐安全收紧.env: CRUD_ADMIN_REQUIRE_PERMISSION=true；登录后立即改 admin 密码admin/admin123 仅种子账号
☐密钥管理config/keys/ 不入 git、不进发布 zip；生产用安装时生成的独立密钥
☐.env 隔离生产独立 .env；绝不复用开发库
