# 快速开始

从零到「后台能登录、能增删改查」的完整流程。已有 webman 项目的话，直接从
[§2 引入插件](#2-引入插件三选一) 看起，然后跳到 [§3 初始化数据库](#3-初始化数据库建表--种子--密钥)。

---

## 1. 前置条件

| 项 | 要求 |
|---|---|
| PHP | ≥ 8.1 |
| 框架 | webman（`workerman/webman-framework` ^2.1，官方骨架即可） |
| 数据库 | MySQL（认证表与业务表**同库**） |
| PHP 扩展 | `ext-gd` + `ext-mbstring` —— 登录图形验证码要用；装不了可在配置里 `'captcha_enabled' => false` |
| 本地环境 | ServBay / phpStudy 等一键环境即可 |

宿主 `composer.json` 需含 webman 官方插件的三个 scripts（官方骨架自带，缺失则补）：

```json
"scripts": {
  "post-package-install":  ["support\\Plugin::install"],
  "post-package-update":   ["support\\Plugin::install"],
  "pre-package-uninstall": ["support\\Plugin::uninstall"]
}
```

并确认存在 `support/Plugin.php`（官方骨架文件；缺失时从 webman 骨架仓库补）。

> 全新项目先建骨架：`composer create-project workerman/webman webman-clean-demo && cd webman-clean-demo`

## 2. 引入插件（三选一）

### 2.1 方式 A：本地 path（开发期联调）

改包源码即时生效，配合包内 `scripts/release.sh` 把宿主侧改动回灌回包：

```bash
composer config repositories.curd path "../webman-curd-admin"
composer require amcolin/webman-curd-admin:@dev
```

### 2.2 方式 B：私有 Git VCS（推荐上线，走 tag 版本）

```bash
# GitHub
composer config repositories.curd vcs "git@github.com:a1586256143/webman-curd-admin.git"
# 国内拉取更快可走 Gitee 镜像：
# composer config repositories.curd vcs "https://gitee.com/colingit/webman-curd-admin.git"

composer require amcolin/webman-curd-admin:^1.0 --no-audit   # 走 tag，避免 @dev 漂移
```

> ⚠️ `composer audit` 红字（`Failed to audit installed packages.`）是**已知尾部告警**：
> audit 硬编码访问 `packagist.org`（不走国内镜像），国内常不可达；命令本身 `exit 0`，
> **不影响安装**。不想每次手打 `--no-audit`：

```bash
# 一次性
./scripts/composer.sh require amcolin/webman-curd-admin:^1.0
# 永久（把系统 composer alias 成 wrapper，只对会触发 audit 的子命令追加 --no-audit）
echo "alias composer='$(pwd)/scripts/composer.sh'" >> ~/.zshrc && source ~/.zshrc
```

### 2.3 方式 C：私有 Satis / Packagist（团队统一源）

仓库已附 `satis.json` 模板（把 homepage / Gitee URL 改成真实地址），
在 Satis 服务器执行 `satis build satis.json web/` 后部署：

```bash
composer config repositories.curd-satis composer "https://satis.your-company.com"
composer require amcolin/webman-curd-admin
```

### 2.4 安装器自动完成了什么（`src/Install.php`，幂等）

1. **拷贝插件**：`vendor/amcolin/webman-curd-admin/plugin/curd` → 宿主 `plugin/curd`
   （**已存在则跳过**，以保护本地开发版）；
2. **示例落位**到宿主根（给你抄的示例，可自由改 / 删）：
   - `app/controller/admin/api/MyTestController.php`（「测试管理」控制器）
   - `app/model/MyTest.php`
3. **生成集中配置** `config/curd-admin.php`（已存在不覆盖）；
4. 宿主 `config/database.php` 缺失或是 webman/database 的占位模板时，自动生成
   **env 驱动**的 `mysql` + `mysql_business` 双连接模板（单库同库）。

```bash
# 验证装好了
ls plugin/curd config/curd-admin.php config/database.php

# 极少见「自动拷贝未触发」时的兜底（注意：这条 cp 会真的覆盖 plugin/curd，先备份再执行）
composer dump-autoload && composer update amcolin/webman-curd-admin
cp -r vendor/amcolin/webman-curd-admin/plugin/curd plugin/curd
```

> 安装器的覆盖边界（哪些动、哪些不动）见 [升级 · 部署 · 发布](08-升级与生产部署.md) §1.1。
> 结论是：**装好之后的配置不会被 `composer update` 覆盖**，但上面这条 `cp -r` 兜底是手工操作，
> 它**会**覆盖 `plugin/curd` 下的本地改动 —— 执行前先 `git status` / 备份。

## 3. 初始化数据库（建表 + 种子 + 密钥）

### 3.1 Web 安装向导（推荐，新项目首选）

```bash
php start.php start      # 端口默认 8787（config/process.php 的 'listen' 行）
```

浏览器打开 **`http://host:port/app/curd-installer`**，填两块（均为明文输入，便于核对）：

- **数据库连接**：主机 / 端口 / 库名 / 账号 / 密码 —— 库不存在会**自动 CREATE**；
- **管理员账号**：登录名 / 密码 / 确认密码 —— 自定义初始管理员，**不是固定的 admin/admin123**。

提交后自动完成：

1. DB 信息**按键合并**写入宿主 `.env`（绝不覆盖其它键）+ 同步写 `config/curd-admin.php`
   的 `database` 段（修复 worker 启动后 `.env` 无法刷新导致的 1045）；
2. 子进程执行 `php plugin/curd/install.php`：自动建库 → 建核心表 + 示例表 `my_test` →
   种子（超级管理员角色 / 基础菜单 /「测试管理」菜单 / 管理员账号 / RSA 密钥）→ 页面实时进度；
3. **免手动重启**：安装成功即向 master 进程发 `SIGUSR1`（= workerman 平滑 reload），
   worker 处理完当前请求后重启并重读 `.env` / config，新 `DB_*` 立即生效（约 2 秒后进登录页）。

> **信号不可用**的场景（Windows / 无 posix 扩展 / supervisor 托管等）页面会自动回退提示
> `php start.php restart` —— worker 配置在启动期固化，不重启会报 `1045 Access denied`。

**安装标记**：成功生成 `runtime/curd-installed.lock`，向导即失效（再访问提示已安装）。
**重装** = 删锁 + 清库后刷新向导页。

### 3.2 CLI 等价流程（不便开浏览器时）

```bash
# 先配好 .env 的 DB_*（键清单见 plugin/curd/env.example，单库只需一份 DB_NAME）
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=webman_curd        # 不存在会自动建
DB_USER=root
DB_PASSWORD=your_password

# 一键安装（幂等，可重复执行；默认只种【超级管理员】角色）
php plugin/curd/install.php --admin-user=admin --admin-pass='你的密码'
```

| 参数 | 说明 |
|---|---|
| `--admin-user=admin` / `--admin-pass=xxx` | 初始管理员凭据（仅 `admin_users` 空表时生效） |
| `--business-sql=path/a.sql` | 项目自带的业务建表 SQL（相对宿主根；可重复或逗号分隔传多个） |
| `--business-connection=mysql_business` | 覆盖业务 SQL 使用的连接名 |
| `--progress-file=runtime/x.log` | 进度 JSONL 输出（Web 向导内部用） |

### 3.3 安装做了什么（幂等，重复执行全部 SKIP）

- **建表**：`admin_users` `admin_tokens` `roles` `admin_role_user` `role_permission`
  `casbin_rule` `curd_configs` `menus`（8 张认证/管理面表）+ 示例表 `my_test`；
- **种子**（仅空表时插）：`roles` 超级管理员、`menus` 6 条基础菜单、初始 admin 账号、
  `curd_configs` 的 `/my-test` 示例页面配置 +「测试管理」菜单 + `my_test` 示例数据；
- **RSA 密钥**：生成 `config/keys/`（已存在跳过；**生产环境务必单独备份此目录**）；
- 所有表 `IF NOT EXISTS`、种子按表空判定 → 重复执行全部 SKIP。

## 4. 全局中间件与异常处理器（必做）

### ① 全局中间件（注册加解密）

插件的接口加解密必须由宿主在 `config/middleware.php` 的 `'@'` 组注册——
`'@'` 才是「跨所有 app 与 plugin 生效」；写成 `''` 只作用于默认 app，插件的 `/api/*` 会绕过：

```php
// config/middleware.php
return [
    '@' => [
        \app\middleware\StaticFile::class,
        // 接口加解密（RSA + AES 信封）；即使当前关闭加密也要保留，否则前端加密请求无人解
        \plugin\curd\app\middleware\ApiCrypto::class,
    ],
];
```

### ② 异常处理器（未捕获异常的兜底出口）

- **插件路由开箱生效**：插件自带 `plugin/curd/config/exception.php`，框架按
  `plugin.curd.exception` 读取，`/api/auth/*`、`/api/curd/*`、`/api/admin/*`、`/api/menu/*` 直接覆盖到；
- **宿主自己的 `/api` 控制器**要覆盖到，就把宿主 `config/exception.php` 的 `''` 键指过来：

```php
// config/exception.php
return [
    '' => \plugin\curd\app\exception\CurdExceptionHandler::class,
];
```

> ⚠️ 只写 `'@'` 键**无效** —— 框架规则是「本 app 配置里已有 `''` 键 ⇒ 忽略 `'@'`」，
> 而 webman 骨架默认就自带 `'' => support\exception\Handler::class`。
>
> ⚠️ **别想用中间件做这件事**：webman 的中间件链在**每一层内层都先 try/catch 再转 Response**，
> 外层中间件**永远捕获不到**控制器抛出的异常（实测踩过）。

**本地 / 线上模式**由 `.env` 的 `APP_DEBUG` 决定（`plugin.curd.app.debug` 读它）：

| `APP_DEBUG` | 行为 |
|---|---|
| `true`（默认，本地） | 异常信息原样暴露：JSON 请求返回真实 msg + traces，其余返回调试页 —— 当场可查 |
| `false`（**线上必设**） | `/api` 返回 **HTTP 500** `{"code":500,"msg":"服务内部错误（编号 xxxxxxxx）"}`，详情写 `runtime/logs/webman.log`，`grep <编号>` 定位原始异常 |

> 宿主自己控制器的模式还取宿主 `config/app.php` 的 `debug`，与插件 debug **取交集**
> （任一为 `false` 即按线上处理），线上记得两边都关。详见
> [接口加密与异常兜底](07-接口加密与异常兜底.md)。

## 6. 写第一个业务 CURD

### 6.1 四步

```php
// ① 模型：app/model/APackage.php —— 启动时自动扫描进 ModelRegistry，不用手写注册
namespace app\model;
use plugin\curd\app\model\BaseModel;

class APackage extends BaseModel {
    protected $table = 'a_package';
}
```

```php
// ② 控制器：app/controller/api/PackageController.php
//    继承插件基类即获得整套列表 / 搜索 / 表单 / 增删改查 / 导出能力
namespace app\controller\api;
use plugin\curd\app\controller\base\BaseCurdController;

class PackageController extends BaseCurdController {
    protected string $modelClass = \app\model\APackage::class;
    protected string $title = '套餐管理';
}
```

```php
// ③ 路由：加入宿主 config/route.php 的 / 或 registerMany([...]) 数组
//    registerMany 是「路径 => 控制器类」的关联数组
RouteControllerRegistry::registerMany([
    '/package' => \app\controller\api\PackageController::class,
]);
// 单条也行：RouteControllerRegistry::register('/package', \app\controller\api\PackageController::class);
```

④ 进后台「菜单管理」登记菜单 + 给角色授权（写 `menus` / `casbin_rule`），前端即可见可用。
**菜单的 `path` 要填上面注册用的路径**（这里是 `/package`）。

> 想省掉手写代码：后台左侧「**配置生成器**」（`/app/curd/curd-generator`）
> 选表 → 配字段 → 填页面路径 → 保存，`/api/curd/config` 立刻能查到该 `route_path`，
> 对应动态页即可在菜单中打开。工具页本身**不需要** DSL 配置。

### 6.2 开箱示例：「测试管理」

装包时示例文件已自动落位宿主根（见 §2.4），启用只要两步：

```php
// a) 宿主 config/route.php 注册（示例文件 MyTestController.php 头注释含完整写法）
RouteControllerRegistry::registerMany([
    // ...
    '/my-test' => \app\controller\admin\api\MyTestController::class,
]);
// b) 安装时已自动种好：my_test 表 + curd_configs 的 /my-test 配置 +「测试管理」菜单
//    重启后打开后台即出现该菜单，直接可增删改查
```

- **全新项目**：安装向导自动建表 + 补菜单 + 插 1 条示例数据，开箱即用。
- **已运行项目**：跑一次 `php plugin/curd/install.php`（幂等）即可补齐表与菜单；不想要就跳过。
- **删除**：控制器 + `app/model/MyTest.php` + `bootstrap.php` 的「内置示例」注册段 +
  menus 里的「测试管理」行 + `my_test` 表（控制器头注释含完整清单）。

这个示例同时是**链路自检**：登录 → 菜单 → 配置接口 → 数据接口 → 库表全通。

## 7. 业务库表结构 · 种子 · 增量 migration

### 7.1 业务建表 SQL

`install.sql` 默认只建认证/管理面那 8 张表。项目专有业务表（如 `hf_goods` /
`mobile_recharge_orders`）由项目自带：放 `install-business.sql` 到项目根，
语句间用 `--SPLIT--` 分隔，`CREATE TABLE IF NOT EXISTS` 保证幂等
（此文件**不**打包进通用包）。

```bash
# 单个文件
php plugin/curd/install.php --business-sql=install-business.sql

# 多个文件（可重复或逗号分隔）
php plugin/curd/install.php \
  --business-sql=sql/admin.sql \
  --business-sql=sql/business.sql

# 临时切换业务库连接（默认 config 的 business_connection，即 mysql_business）
php plugin/curd/install.php \
  --business-sql=install-business.sql \
  --business-connection=mysql_business_test
```

执行机制：`Install::install(false, $extraSqls)` → `Install::runSqlFile($content, $db, true)`
（先把内容读入再传，避免路径被当 SQL 语句）。每条额外 SQL 走各自指定的 DB 连接，
与认证库完全隔离。

### 7.2 业务种子（菜单 / 权限自动登记）

新环境想「装完即带业务菜单」，把菜单 / 权限的种子 INSERT 直接追加到业务 SQL 里，
全部用 `INSERT IGNORE` 保持幂等（`--SPLIT--` 分隔语句）：

```sql
-- install-business.sql（项目根；表结构部分见上一节）
-- 菜单：path 必须与 RouteControllerRegistry 注册的路径一致
INSERT IGNORE INTO menus (parent_id, title, icon, path, permission, sort, type, visible)
VALUES (0, '测试管理', 'Monitor', '/my-test', 'curd:MyTest', 90, 1, 1);
--SPLIT--
-- 权限：admin 角色已带 p,admin,*,* 通配，通常只需给其它角色补
INSERT IGNORE INTO casbin_rule (ptype, v0, v1, v2)
VALUES ('p', 'yunying', 'curd:MyTest', '*');
```

字段口径（与 `install.sql` 的 DDL 一致）：

| 表 | 关键列 |
|---|---|
| `menus` | `parent_id`（0 = 顶级）、`title`（菜单名）、`icon`（Element Plus 图标名）、`path`（路由路径）、`permission`（权限标识）、`sort`、`type`（1 = 菜单项 / 2 = 子菜单容器）、`visible` |
| `casbin_rule` | `ptype`（`p` = 策略 / `g` = 角色继承）、`v0`（角色）、`v1`（obj）、`v2`（act） |

> 菜单的 `path` 推导权限标识的规则是 `curd.{Model}`；`permission` 留空时由后台
> 「一键生成权限」按已注册的 CURD 页推导。详见 [菜单与权限](05-菜单与权限.md)。

### 7.3 增量 migration（表结构演进）

业务表结构变更用**只追加**的迁移文件，由 `plugin/curd/migrate.php` 驱动：

```bash
# 文件命名：plugin/curd/migrations/V{版本}__{描述}.sql，版本号升序，--SPLIT-- 分隔多语句
php plugin/curd/migrate.php                       # 跑全部未执行迁移
php plugin/curd/migrate.php --connection=mysql    # 指定连接
php plugin/curd/migrate.php --dry-run             # 预检
```

- 已执行版本记录进 `{连接库}._curd_migrations`（唯一约束，幂等）；
- 已发布版本**只追加不修改**，改结构请新建更高版本号文件；
- 详见 `plugin/curd/migrations/README.md`。

## 8. 配置写在哪个文件

| 内容 | 写在哪 |
|---|---|
| 数据库连接（`DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASSWORD`） | 宿主 `.env`（由 `config/database.php` 用 `env()` 读取；向导会自动写） |
| 插件调参 + 站点信息 + 验证码 + 上传 + 导出上限 | 宿主根 **`config/curd-admin.php`**（唯一入口） |
| ❌ 不再读取 | `config/curd.php`、`config/admin.php`（2026-09-19 已合并，存在也不生效） |

配置改完**必须重启 webman**（启动期读取）；只有 `site` / `home_page` / `captcha_*`
这几项无需重建前端。全部键位与默认值见 [配置参考](02-配置参考.md)。
