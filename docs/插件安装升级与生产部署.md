> 适用版本：2026-09-06（单库架构 + Web 安装向导自动生效，向导安装免手动重启）

> 关系说明：`plugin/curd` 与发布包 `amcolin/webman-curd-admin`（Gitee：

## 1. 架构与配置（单库模型，v1.1 起）

**数据库信息只写宿主 `.env` 的 5 个键**：`DB_HOST / DB_PORT / DB_NAME / DB_USER / DB_PASSWORD`。
自动生成的 `config/database.php` 用 `env()` 读取它们（`src/Install.php` 内置模板）。

- **强制单库**：认证表（`admin_users / admin_tokens / roles / admin_role_user /
  role_permission / casbin_rule / curd_configs / menus`）与业务表**放同一个库**，已无
  `DB_BUSINESS_NAME`、无"分库选项/同库勾选"。
- `mysql_business` 连接仍保留（兼容已写死 `$connection='mysql_business'` 的模型），其
  `database` 与 `mysql` 相同（= `DB_NAME`）。
- **插件调参**（`admin_connection / business_connection / page_base /
  admin_require_permission`）不再读 `CURD_*` 环境变量，统一写宿主 `config/curd.php`
  顶层同名键（缺失时首次引入自动生成默认模板，不覆盖 .env 任何键）。

> ⚠️ **本宿主现状（重要）**：宿主根 `config/database.php` 是**手工维护的分库版**
> （`mysql` = `DB_NAME`，`mysql_business` = `DB_BUSINESS_NAME`），且业务模型基类
> `app/model/BaseModel` 固定 `$connection = 'mysql_business'`。**维持分库布局时**
> `.env` 保留 `DB_BUSINESS_NAME` 即可，与新插件代码不冲突（插件只认 `admin_connection`/
> `business_connection` 两个连接名，两个连接都定义着）。仅当某个新环境想切单库时：
> 去掉 `DB_BUSINESS_NAME` 键，并把 `config/database.php` 里 `mysql_business.database`
> 改为 `env('DB_NAME')`（或直接使用自动生成模板）。

## 2. 从包引入全新项目（composer require）

```bash
# ① 全新项目：先建 webman 骨架（已有项目跳过，直接 ②）
composer create-project workerman/webman webman-clean-demo
cd webman-clean-demo

# ② 配置源（三选一）
composer config repositories.curd path "~/Public/www/company/webman-curd-admin"   # 本地 path（包仓库开发期，改包即生效，路径换成你本包真实路径）
#    或 VCS（上线走 tag 版本）：composer config repositories.curd vcs "https://github.com/a1586256143/webman-curd-admin"
#    或公司 Satis：composer config repositories.curd composer https://satis.your-company.com

# ③ 引入（require 自动完成：拉齐依赖 webman/database + webman/redis + casbin/casbin +
#    vlucas/phpdotenv；webman 官方插件机制自动拷贝 plugin/curd 到宿主；
#    宿主缺 config/database.php 自动按 env() 模板生成；缺 config/curd.php 自动生成调参模板）
composer require amcolin/webman-curd-admin:dev-main --no-audit
#   ⚠️ audit 红字（audit 硬编码访问 packagist.org，国内常不可达）仅尾部告警、exit 0；
#   彻底消除：alias composer='<包仓库>/scripts/composer.sh'（只对会触发 audit 的子命令加 --no-audit）

# ④ 验证
ls plugin/curd config/database.php config/curd.php
```

## 3. Web 安装向导（新项目首选，/app/curd-installer）

```bash
# ① 先启动服务（向导依赖服务在线；端口在 config/process.php 的 'listen'，默认 8787）
php start.php start

# ② 浏览器打开
#    http://host:port/app/curd-installer

# ③ 安装后进入后台管理
#    http://host:port/app/curd
```

表单（均为**明文输入**，便于核对）：
- 数据库连接：主机 / 端口 / **库名** / 账号 / 密码 —— 库不存在自动创建；**强制单库**
  （认证 + 业务同库，界面已注明，无分库选项）
- 管理员账号：登录名 / 密码 / 确认密码（自定义初始管理员，非固定 admin/admin123）

提交后自动完成：
1. DB 信息**按键合并**写入宿主 `.env`（绝不覆盖其它键，并自动剔除遗留 `DB_BUSINESS_NAME`）；
2. 子进程执行 `php plugin/curd/install.php`：自动建库 → 建核心表 + 后台示例表 `my_test` →
   种子（仅超级管理员角色 / 基础菜单 /「测试管理」菜单 / 管理员账号 / RSA 密钥）→ 页面实时进度；
3. **免手动重启**：安装成功即向 master 进程发 `SIGUSR1`（= workerman 平滑 reload），worker
   处理完当前请求后重启并重读 `.env`/config，新 `DB_*` 立即生效（约 2 秒后自动进入登录页）。
   reload 不可用的场景（Windows / 无 posix 扩展 / supervisor 托管等）页面自动回退提示
   `php start.php restart`，不会误导。

**安装标记**：成功生成 `runtime/curd-installed.lock`，向导即失效（再次访问提示已安装）。
**重装**：删除该锁 + 清空数据库后刷新向导页。

### CLI 安装（向导的等价手动流程）

```bash
php plugin/curd/install.php --admin-user=admin --admin-pass='你的密码'
#   可选：--progress-file=runtime/i.log（JSONL 进度）、--business-sql=路径（可多个/逗号分隔）
```

## 4. 后台示例「测试管理」（my_test / MyTestController）

登录后台左侧可见「测试管理」（`/my-test`）：`my_test` 表 + `MyTestController`（数组式
`BaseCurdController` 写法），提供完整搜索/增删改查/导出，作为**新控制器最小参考**与
**链路自检**（登录 → 菜单 → 配置接口 → 数据接口 → 库表全通）。

- **全新项目**：安装向导自动建表 + 补菜单 + 插 1 条示例数据，开箱即用。
- **本宿主等已运行项目**：跑一次 `php plugin/curd/install.php`（幂等）即可补齐
  `my_test` 表 +「测试管理」菜单；不想要示例就跳过，不影响安装结果。
- **删除**：控制器 + `app/model/MyTest.php` + `bootstrap.php`「内置示例」注册段 +
  menus「测试管理」行 + `my_test` 表（控制器头注释含完整清单）。

## 5. 宿主内插件升级 / 随包同步

本宿主是**嵌入开发**（plugin/curd 直接放宿主），升级 = 用包仓库代码覆盖，按需提交。

```bash
# ① 先查宿主 plugin/curd 有无本地改动（有则先备份/处理）
<包仓库>/scripts/check-plugin-overrides.sh .

# ② 备份 + 重拷（包仓库脚本，含 install-business 等宿主文件保护）
<包仓库>/scripts/sync-plugin.sh
#    或手工按第 6 节清单拷贝
```

**同步清单（包 → 宿主 plugin/curd）**：`api/Install.php`、`app/`（bootstrap /
controller/InstallerController.php / MyTestController.php / model/MyTest.php）、
`config/curd.php`、`config/route.php`、`env.example`、`install.php`、`install.sql`、
`public/installer/`、`database.business.example.php`。

**宿主专有文件，绝不能覆盖/删除**：
| 文件 | 说明 |
|---|---|
| `plugin/curd/config/keys/` | RSA 私钥（`.gitignore` 排除，换机需手动拷贝，丢失要重生成） |
| `plugin/curd/install-business.sql` | 宿主真实业务建表 SQL（`--business-sql` 用它，128 行） |
| `plugin/curd/public/assets/` | 宿主前端构建产物（`frontend/` 独立构建） |
| 宿主根 `config/database.php` / `.env` / `app/` | 插件之外的宿主自有层 |

> 宿主业务表建表：`php plugin/curd/install.php --business-sql=plugin/curd/install-business.sql`
> （幂等，`--SPLIT--` 分句，IF NOT EXISTS）。

## 6. 生产部署（supervisor + nginx + 备份）

### 6.1 守护进程 supervisor

```ini
# /etc/supervisor/conf.d/my-app.conf
[program:my-app]
command=php /var/www/my-app/start.php start
directory=/var/www/my-app
numprocs=1
autostart=true
autorestart=true
startretries=3
user=www-data
redirect_stderr=true
stdout_logfile=/var/log/my-app/worker.log
```

```bash
supervisorctl reread && supervisorctl update && supervisorctl start my-app
```

> 不要裸跑 `php start.php start -d`。托管后整体重启用 `supervisorctl restart my-app`
> （手动 `php start.php restart` 会杀会话进程组）。插件 Web 向导的 `SIGUSR1` reload
> 只平滑重启 worker、不杀 master，与 supervisor 托管兼容，可用作"改配置即时生效"。

### 6.2 Nginx 反代（SPA 与 API 同域，免 CORS）

```nginx
server {
    listen 80;
    server_name admin.example.com;
    root /var/www/my-app/public;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }
    location /index.php {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root/index.php;
        fastcgi_pass 127.0.0.1:8787;   # 与 config/process.php 'listen' 一致（webman 2.x 端口在此）
    }
    location /app/curd/ {              # 插件内置前端（SPA history 由 PageController 处理）
        try_files $uri $uri/ /index.php?$query_string;
    }
}
```

### 6.3 环境与密钥

- 开发 / 测试 / 生产各用独立数据库，`.env` 的 `DB_*` 按环境填写；`.env` 不进 git。
- 生产至少：`config/curd.php` 开 `admin_require_permission => true`；登录后立即修改
  管理员密码；`config/keys/` 独立挂载、不进 git / 不进发布产物。
- 反代真实 IP：webman 取 `connection->getRemoteIp()`，依赖 Nginx 正确透传。

### 6.4 备份

| 对象 | 频率 | 方式 |
| --- | --- | --- |
| 认证库（admin_users / roles / menus / casbin_rule…） | 每日 | mysqldump 全量 + 保留 7 天 |
| 业务库 | 每日 | 同上 |
| `config/keys/`（RSA 私钥） | 生成即备份 | 单独加密归档，切勿丢失 |
| 代码 / 前端 dist | 每次发版 | git tag + CI 产物 |

### 6.5 升级回滚

升级前 `check-plugin-overrides.sh` 确认无本地改动；升级后跑一次 `php plugin/curd/install.php`
（幂等补种子/新表/菜单）。回滚：`git checkout <上一版本 tag>` 或 composer 锁版本重装。

## 7. 踩坑速查（安装/部署）

| 现象 | 原因 / 解法 |
|---|---|
| 向导完成后后台报 1045 Access denied | 老版本需手动 restart；v1.1 向导已自动 SIGUSR1 reload。若在 supervisor/Windows 场景页面会提示手动 `php start.php restart` |
| 向导页面显示"系统已安装" | `runtime/curd-installed.lock` 存在；重装 = 删锁 + 清库刷新 |
| `Failed to audit installed packages` 红字 | audit 访问 packagist.org 被墙，exit 0 不影响安装；alias 到 `scripts/composer.sh` 消除 |
| `Class "support\Redis" not found` | 缺 `webman/redis`：`composer require webman/redis`（包已 require，旧宿主补装） |
| my_test /「测试管理」不出现 | 老项目没跑过新 install；执行一次 `php plugin/curd/install.php`（幂等补表补菜单） |
| 改 PHP 类/配置后不生效 | webman 常驻内存：reload 重读 .env/config 与类文件需重启（向导场景已自动 reload） |
| 端口不是 8787 | webman 2.x 端口在 `config/process.php` 的 `listen`，改这里再重启 |
