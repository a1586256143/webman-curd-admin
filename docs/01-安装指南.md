# 安装指南（空项目 → 后台能登录）

从**一个空目录**开始，把 webman 骨架 + 本插件装到「浏览器能打开登录页、能增删改查」为止。
每一步都给了**验收点**（做完应该看到什么）和**失败怎么办**（对应常见问题编号，详见
[排错速查与 FAQ](16-排错速查与FAQ.md)）。

> 已经有能跑的 webman 项目？跳过 [§1](#1-环境自检) [§2](#2-建-webman-空项目)，
> 从 [§3 引入插件](#3-引入插件三选一) 开始，做完 §8 即可。
> 只想看「装完之后怎么写业务页面」→ 直接读 [快速开始](02-快速开始.md)。

---

## 0. 全流程地图

```
① 环境自检  →  ② 建 webman 骨架  →  ③ composer require 插件
      ↓                                     ↓
   缺什么补什么                     自动生成 plugin/curd + config/curd-admin.php
                                            ↓
④ 配数据库(.env) → ⑤ 初始化建表(向导/CLI) → ⑥ 宿主注册中间件+异常处理器
                                            ↓
                            ⑦ 启动 → ⑧ 验收（登录页 / 接口）
                                            ↓
                            ⑨ 写第一个业务 CURD（见 快速开始）
```

| 步骤 | 大概耗时 | 会改哪些文件 |
|---|---|---|
| ① 环境自检 | 2 分钟 | 无 |
| ② 建骨架 | 2 分钟 | 新建项目目录 |
| ③ 引入插件 | 2 分钟 | `composer.json`、`plugin/curd/`、`config/curd-admin.php`、`app/`（示例） |
| ④ 配数据库 | 1 分钟 | `.env`（或 `config/database.php`） |
| ⑤ 初始化 | 1 分钟 | 数据库 8 张表 + `config/keys/*.pem` + `runtime/curd-installed.lock` |
| ⑥ 宿主接线 | 3 分钟 | `config/middleware.php`、`config/exception.php` |
| ⑦⑧ 启动验收 | 1 分钟 | 无 |

## 1. 环境自检

### 1.1 要求

| 项 | 最低要求 | 说明 |
|---|---|---|
| PHP | **8.1+** | 插件用了 `enum`、`readonly`、`never` 等语法，8.0 及以下直接语法报错 |
| 扩展 | `pdo_mysql` `mbstring` `gd` `openssl` `json` | `gd` 只给登录图形验证码用，装不了可关（见 §4.3） |
| MySQL | 5.7+ / 8.0+ | 单库架构：认证表与业务表放**同一个库** |
| Composer | 2.x | |
| 进程管理 | 无需额外组件 | webman 自带 workerman，CLI 启动即可 |

### 1.2 一条命令自检

```bash
php -v && php -m | grep -Ei 'pdo_mysql|mbstring|gd|openssl|posix' && composer -V && mysql --version
```

期望看到 `PHP 8.1.x` 或更高，以及 `pdo_mysql` / `mbstring` / `gd` / `openssl` / `posix` 五行。
`posix` 缺失不影响启动，只影响「Web 安装向导装完自动平滑重启」（会回退成提示你手动 restart）。

### 1.3 缺什么怎么补

| 缺 | 处理 |
|---|---|
| PHP 版本低 | 换 8.1+。ServBay / phpStudy / brew 都能多版本共存；`php -v` 要确认**命令行用的那个**也是 8.1+ |
| `pdo_mysql` | 打开 `php.ini` 的 `extension=pdo_mysql`（Windows 是 `extension=php_pdo_mysql.dll`） |
| `mbstring` | 同上，`extension=mbstring` |
| `gd` | `extension=gd`；实在装不了就在 `config/curd-admin.php` 设 `'captcha_enabled' => false` |
| `openssl` | 一般默认开启；关闭时接口加密与 RSA 密钥生成都不可用 |
| 没有 composer | `curl -sS https://getcomposer.org/installer \| php` 或包管理器安装 |

> 命令行 PHP 与 Nginx/Apache 用的 PHP **可能不是同一个**。`php -v` 对、但浏览器 500，
> 先确认 FPM 那侧的版本（[FAQ §2](16-排错速查与FAQ.md#2-启动--运行)）。

## 2. 建 webman 空项目

```bash
composer create-project workerman/webman webman-curd-demo
cd webman-curd-demo
```

### 2.1 确认骨架自带「插件安装三件套」

webman 官方骨架的 `composer.json` 里应包含这三行 —— 插件的自动拷贝全靠它们：

```json
"scripts": {
  "post-package-install":  ["support\\Plugin::install"],
  "post-package-update":   ["support\\Plugin::install"],
  "pre-package-uninstall": ["support\\Plugin::uninstall"]
}
```

并确认 `support/Plugin.php` 存在：

```bash
ls support/Plugin.php && grep -n 'post-package-install' composer.json
```

> **缺了会怎样**：`composer require` 成功，但 `plugin/curd/` 目录不会被创建，
> 后台 404。补上这两处后再 `composer dump-autoload && composer update amcolin/webman-curd-admin`。
> 见 [FAQ §1](16-排错速查与FAQ.md#1-安装--初始化)。

### 2.2 先跑一次空骨架

```bash
php start.php start
# 浏览器打开 http://127.0.0.1:8787 → 看到 webman 欢迎页即骨架 OK
```

端口在 `config/process.php` 的 `'listen' => 'http://0.0.0.0:8787'`。
**先确认空骨架能跑，再装插件** —— 出问题时才能区分是骨架问题还是插件问题。

## 3. 引入插件（三选一）

### 3.1 方式 A：本地 path（开发期联调，改包源码即时生效）

```bash
composer config repositories.curd path "../webman-curd-admin"
composer require amcolin/webman-curd-admin:@dev
```

包在本机其它位置就把 `../webman-curd-admin` 换成实际路径。改包内源码不用重新 require。

### 3.2 方式 B：Git VCS（推荐上线，走 tag 版本）

```bash
# GitHub
composer config repositories.curd vcs "git@github.com:a1586256143/webman-curd-admin.git"
# 国内更快可走 Gitee 镜像：
# composer config repositories.curd vcs "https://gitee.com/colingit/webman-curd-admin.git"

composer require amcolin/webman-curd-admin:^1.0 --no-audit
```

### 3.3 方式 C：私有 Satis / Packagist（团队统一源）

```bash
composer config repositories.curd-satis composer "https://satis.your-company.com"
composer require amcolin/webman-curd-admin
```

仓库内附 `satis.json` 模板，改掉 `homepage` / Gitee URL 后在 Satis 服务器
`satis build satis.json web/` 即可。

### 3.4 关于 `--no-audit`

`composer audit` 红字（`Failed to audit installed packages.`）是**已知尾部告警**：
它硬编码访问 `packagist.org`，不走国内镜像，国内常不可达；命令本身 `exit 0`，
**不影响安装**。不想每次手打：

```bash
./scripts/composer.sh require amcolin/webman-curd-admin:^1.0        # 一次性
echo "alias composer='$(pwd)/scripts/composer.sh'" >> ~/.zshrc      # 永久（wrapper 只对会触发 audit 的子命令追加 --no-audit）
```

### 3.5 安装器自动做了什么

`src/Install.php`（由 `support\Plugin::install` 调用）会：

| # | 动作 | 落点 | 已存在时 |
|---|---|---|---|
| 1 | 拷贝插件 | `plugin/curd/` | **整目录覆盖重拷**（清掉包内已删除的陈旧文件），仅保留 `config/keys/*.pem` |
| 2 | 落位示例 | `app/controller/admin/api/MyTestController.php`、`app/model/MyTest.php` | 不覆盖 |
| 3 | 生成配置 | `config/curd-admin.php` | 不覆盖 |
| 4 | 生成翻译文件 | `resource/translations/zh_CN/fields.php` | 不覆盖 |
| 5 | 补数据库模板 | `config/database.php`（缺失或是占位模板时） | 不覆盖 |

### 3.6 验收：装好了吗

```bash
ls plugin/curd/config/route.php config/curd-admin.php
php -r 'echo is_file("plugin/curd/api/Install.php") ? "plugin OK\n" : "plugin MISSING\n";'
```

三条都在 → 继续。`plugin MISSING` → 见 [FAQ §1](16-排错速查与FAQ.md#1-安装--初始化)
（九成是 §2.1 的三件套缺失，或 `extra.webman-app-plugin` 被改）。

## 4. 配数据库

数据库连接**不在** `config/curd-admin.php`，而是走 `.env` 的 `DB_*` 键
（`config/database.php` 用 `env()` 读）。两种做法，任选一种：

### 4.1 做法一：什么都不填，交给安装向导（推荐）

直接跳到 [§5.1](#51-web-安装向导推荐新项目首选)，向导页面上填主机 / 库名 / 账号密码，
提交后自动写 `.env` 并同步 `config/curd-admin.php` 的 `database` 段。

### 4.2 做法二：自己写 `.env`

在项目根 `.env` 追加（键清单见 `plugin/curd/env.example`）：

```ini
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=webman_curd
DB_USER=root
DB_PASSWORD=your_password
```

> **单库**：认证表与业务表同库，只需一份 `DB_*`。`config/database.php` 里
> `mysql` 与 `mysql_business` 两个连接指向同一个库，业务想分库才需要动它。

### 4.3 顺手确认验证码开关

装不了 `ext-gd` 的话，在 `config/curd-admin.php` 里改：

```php
'captcha_enabled' => false,   // 关掉登录图形验证码
```

## 5. 初始化数据库（建表 + 种子 + 密钥）

### 5.1 Web 安装向导（推荐，新项目首选）

```bash
php start.php start
```

浏览器打开 **`http://127.0.0.1:8787/app/curd-installer`**，填两块（明文输入，便于核对）：

1. **数据库连接**：主机 / 端口 / 库名 / 账号 / 密码 —— 库不存在会**自动 CREATE**；
2. **管理员账号**：登录名 / 密码 / 确认密码 —— 自定义初始管理员，**不是固定的 admin/admin123**。

提交后自动完成：

1. DB 信息**按键合并**写入 `.env`（绝不覆盖其它键）+ 同步写 `config/curd-admin.php` 的
   `database` 段（修掉「worker 启动后 `.env` 改不动」导致的 1045）；
2. 子进程执行 `php plugin/curd/install.php`：建库 → 建表 → 种子 → RSA 密钥 → 页面实时进度；
3. **免手动重启**：成功后向 master 进程发 `SIGUSR1`（workerman 平滑 reload），
   worker 处理完当前请求即重启并重读 `.env`（约 2 秒后进登录页）。

> **信号不可用**（Windows / 无 `posix` 扩展 / supervisor 托管）时，页面会提示你手动
> `php start.php restart` —— worker 配置在启动期固化，不重启会报 `1045 Access denied`。

**验收**：浏览器跳到 `/app/curd/` 登录页，用刚设的账号能登录。
安装标记文件 `runtime/curd-installed.lock` 生成后，向导自动失效。

### 5.2 CLI 等价流程（不便开浏览器 / 自动化部署）

```bash
# 前提：.env 的 DB_* 已配好（见 §4.2）
php plugin/curd/install.php --admin-user=admin --admin-pass='你的密码'
```

| 参数 | 说明 |
|---|---|
| `--admin-user=admin` / `--admin-pass=xxx` | 初始管理员凭据（仅 `admin_users` 空表时生效） |
| `--business-sql=path/a.sql` | 项目自带业务建表 SQL（相对宿主根；可重复或逗号分隔） |
| `--business-connection=mysql_business` | 覆盖业务 SQL 使用的连接名 |
| `--progress-file=runtime/x.log` | 进度 JSONL 输出（Web 向导内部用） |

### 5.3 这一步到底建了什么

- **8 张管理面表**：`admin_users` `admin_tokens` `roles` `admin_role_user`
  `role_permission` `casbin_rule` `curd_configs` `menus`，外加示例表 `my_test`；
- **种子**（仅空表时插）：超级管理员角色、6 条基础菜单、初始 admin 账号、
  `/my-test` 示例页面配置 +「测试管理」菜单 + 示例数据；
- **RSA 密钥**：`config/keys/api_rsa_priv.pem` / `api_rsa_pub.pem`
  —— **生产环境务必单独备份此目录**，换机器重装会重新生成，旧密钥加密的历史数据解不开。

> 全程幂等：表用 `CREATE TABLE IF NOT EXISTS`，种子按「表空才插」判定，
> 重复执行全部 SKIP。**重装** = 删 `runtime/curd-installed.lock` + 清库 + 刷新向导页。

## 6. 宿主接线（两处，必做）

插件自己的路由开箱生效，但**加解密中间件**与**宿主 `/api` 的异常兜底**必须宿主登记。

### 6.1 全局中间件：`config/middleware.php`

```php
return [
    '@' => [
        \app\middleware\StaticFile::class,
        // 接口加解密（RSA + AES 信封）；即使当前关闭加密也要保留，否则前端加密请求无人解
        \plugin\curd\app\middleware\ApiCrypto::class,
    ],
];
```

> 必须是 `'@'`（跨所有 app 与 plugin 生效）。写成 `''` 只作用于默认 app，
> 插件的 `/api/*` 会绕过 → 加密开启时全部请求解密失败。

### 6.2 异常处理器：`config/exception.php`

- **插件路由已开箱生效**：插件自带 `plugin/curd/config/exception.php`，覆盖
  `/api/auth/*`、`/api/curd/*`、`/api/admin/*`、`/api/menu/*`；
- **宿主自己的 `/api` 控制器**要覆盖到，才需要把宿主 `config/exception.php` 的 `''` 键指过来：

```php
return [
    '' => \plugin\curd\app\exception\CurdExceptionHandler::class,
];
```

> ⚠️ 只写 `'@'` 键**无效** —— 框架规则是「本 app 配置里已有 `''` 键 ⇒ 忽略 `'@'`」，
> 而 webman 骨架默认就自带 `'' => support\exception\Handler::class`。
>
> ⚠️ 别想用中间件做这件事：webman 中间件链在每层内层都先 try/catch 转 Response，
> 外层中间件**永远捕获不到**控制器异常（实测踩过）。

`APP_DEBUG` 决定模式：`true`（本地）异常原样暴露；`false`（**线上必设**）返回
`{"code":500,"msg":"服务内部错误（编号 xxxxxxxx）"}`，详情写
`runtime/logs/webman.log`，`grep <编号>` 定位。详见 [接口加密与异常兜底](14-接口加密与异常兜底.md)。

## 7. 启动

```bash
php start.php restart     # CLI 安装后必须重启一次（Web 向导已自动平滑 reload，可跳过）
```

| 命令 | 用途 |
|---|---|
| `php start.php start` | 前台启动（调试看日志用，`Ctrl+C` 退出） |
| `php start.php start -d` | 守护进程（后台常驻） |
| `php start.php restart` | 重启（**改 PHP 代码 / 配置后必须**） |
| `php start.php reload` | 平滑重载业务代码（不发 SIGUSR1 时用） |
| `php start.php status` | 看进程与连接数 |
| `php start.php stop` | 停止 |

> **webman 是常驻内存**：改 PHP 代码或配置不 restart 不生效。这条会反复踩，
> 已写进 [总览 §5 三条约定](00-总览与导航.md#5-三条必须记住的约定)。

## 9. 可能遇到的问题

按「现象」查。全部条目的完整版在 [排错速查与 FAQ](16-排错速查与FAQ.md)，这里只列安装期高频项。

### 9.1 安装期（composer）

| 现象 | 原因 | 解决 |
|---|---|---|
| `composer require` 报 `Could not find package` | 仓库没配，或 `@dev` 没带 | 方式 A 必须 `amcolin/webman-curd-admin:@dev`；方式 B 先 `composer config repositories.curd vcs ...` |
| `Your requirements could not be resolved`（`minimum-stability`） | 宿主 `minimum-stability` 是 `stable`，而 `@dev` 分支版本不满足 | 用 `@dev` 显式声明，或走 tag `^1.0`（方式 B） |
| `composer audit` 报红 / 卡住 | audit 直连 `packagist.org`，国内不可达 | 加 `--no-audit`，或 alias `scripts/composer.sh`（§3.4） |
| `require` 成功但 `plugin/curd` 不存在 | 宿主缺 `post-package-install` 三件套 / 缺 `support/Plugin.php` | 补 §2.1，再 `composer dump-autoload && composer update amcolin/webman-curd-admin` |
| 想强制重装插件目录 | 自动拷贝没触发 | ⚠️ 先备份：`cp -r vendor/amcolin/webman-curd-admin/plugin/curd plugin/curd` 会**覆盖本地改动** |
| `composer remove` 后 `plugin/curd` 还在 | `pre-package-uninstall` 未注册 | 手动删 `plugin/curd`（数据表与 `config/curd-admin.php` 不会自动删，见 §10） |

### 9.2 初始化期（建表 / 连接）

| 现象 | 原因 | 解决 |
|---|---|---|
| `1045 Access denied for user` | 装完后没重启，worker 还用旧 `.env` | `php start.php restart`（向导场景确认 `posix` 可用） |
| `SQLSTATE[HY000] [2002] Connection refused` | 主机 / 端口错，或 MySQL 没起 | 核对 `DB_HOST` / `DB_PORT`；容器里跑要写 `host.docker.internal` 或服务名 |
| 向导页打不开（404） | 已装过（`runtime/curd-installed.lock` 存在）或路由未加载 | 删锁重装，或走 CLI（§5.2） |
| 向导提交后卡住不动 | 子进程 `install.php` 报错，进度没写 | 看 `runtime/logs/webman.log`；或直接命令行跑 §5.2 看真实报错 |
| 建表成功但后台空白 | 种子没插（表非空被 SKIP） | 清空对应表后重跑 `php plugin/curd/install.php` |
| `config/keys` 丢了 | 覆盖同步时被清（正常应保留 `*.pem`） | 从备份恢复；没有就重新生成并让前端重新登录 |

### 9.3 运行期（页面 / 接口）

| 现象 | 原因 | 解决 |
|---|---|---|
| `/app/curd/` 404 | `PageController` 未加载 / 被宿主路由覆盖 | 确认 `plugin/curd/public/index.html` 存在，检查 `config/route.php` 有无同名兜底路由 |
| 页面白屏、控制台 `MIME type` / `Failed to load module` | 前端产物被当文本返回 / 静态文件没走对 | Nginx 见 [升级 · 部署](15-升级与生产部署.md) §4；本地确认 `StaticFile` 中间件在 `'@'` 组 |
| 登录一直转圈 / 401 | `ApiCrypto` 没注册（§6.1），前端加密请求后端不认 | 把 `ApiCrypto` 加到 `'@'` 组并 restart |
| 500 且日志 `Undefined array key "locale"` | 宿主缺 `config/plugin/curd/translation.php` | 重装（插件自带该文件）或从包内补一份 |
| 500 且日志 `Base table or view not found: curd_configs` | 没跑初始化 | §5 |
| 验证码不显示 | 缺 `ext-gd` | 装 gd，或 `'captcha_enabled' => false` |
| 登录后菜单是空的 | 角色没授权 / `permission_enabled` 干扰 | 见 [菜单与权限](12-菜单与权限.md) |
| 改配置没反应 | 改错文件（旧 `config/curd.php` 已不读）或没 restart | 只认 `config/curd-admin.php` + restart |
| 跨域 `CORS` 报错 | 前端与后端不同源 | 插件自带 `Cors` 中间件；确认它没被宿主 `'@'` 组顺序挤掉 |

> 更多现象（DSL 不生效、Action 404、导出乱码、加密开关、异常编号定位…）见
> [排错速查与 FAQ](16-排错速查与FAQ.md)。

## 10. 卸载与重装

```bash
# 卸载（pre-package-uninstall → 删除 plugin/curd）
composer remove amcolin/webman-curd-admin && php start.php restart

# 重来一次
rm -f runtime/curd-installed.lock        # 让安装向导重新可用
composer update amcolin/webman-curd-admin # 重新触发插件拷贝
php plugin/curd/install.php --admin-user=admin --admin-pass='新密码'
php start.php restart
```

`composer remove` **不会**删：数据库表（含业务数据）、`config/curd-admin.php`、
示例控制器 / 模型、`resource/translations/`、`config/keys/`。
逐项清单与「哪些属于宿主不能覆盖」见 [升级 · 部署 · 发布 §3](15-升级与生产部署.md#3-卸载)。
