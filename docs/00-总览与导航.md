# webman-curd-admin · 总览与导航

面向 webman 的**中后台一体化应用插件**：CURD / DSL / Schema 页面引擎 + 登录 / RBAC 底座 + 内置前端。
宿主一条 `composer require`，插件自动落到 `{项目}/plugin/curd`，启动即用 ——
**不需要单独部署任何前端静态资源，也不需要写 List / Form / API 代码**。

| 项 | 值 |
|---|---|
| 包名 | `amcolin/webman-curd-admin` |
| 插件目录 | `plugin/curd`（宿主根；由 webman 官方插件机制 `support\Plugin::install` 自动拷贝） |
| 命名空间 | `plugin\curd\app\*` |
| 配置读取 | `config('plugin.curd.*')`（插件调参） + `config('curd-admin.*')`（宿主管家键） |
| 路由前缀 | `/api/*`（后端 API）、`/app/curd/*`（内置前端 SPA） |
| 仓库 | GitHub `a1586256143/webman-curd-admin`；Gitee 镜像 `colingit/webman-curd-admin` |

## 3. 两类 DSL 与文件归属（先读这一段）

插件提供**通用引擎**，业务项目在 **app 层**消费它，两者严格分工：

| DSL | 用途 | 形态 | 代码位置 |
|---|---|---|---|
| **Schema 页面 DSL** | 展示型页面（首页 / 看板）：组件套组件 + 24 栏栅格 + 数据注入 | `PageSchema + blocks` 编译成 JSON 组件树 | `plugin/curd/app/schema/` |
| **CURD DSL** | 列表管理页：表格 / 搜索 / 表单 / 自定义操作 / 导出 / 汇总条 | `Grid / Form / Filter / Column / Action` 流式声明 | `plugin/curd/app/dsl/` |

| 内容 | 归属 | 说明 |
|---|---|---|
| Schema 引擎（`SchemaNode` / `PageSchema` / `PageRegistry` / `blocks/*`） | 插件 `plugin/curd/app/schema/` | 命名空间 `plugin\curd\app\schema\*`，与业务无关 |
| 自定义页面分发控制器 `CustomPageController`（`.vue` + Schema 两种分发） | 插件 | 路由在插件 `plugin/curd/config/route.php` |
| 页面内容接口 `GET /api/custom/pages`、`GET /api/custom/page` | 插件 | 随插件自动加载 |
| **业务 Schema 页面类**（如首页 `HomePage`） | 业务 `app/controller/admin/api/` | 用户级文件，自己 `use` 插件 DSL |
| Schema 页面**数据接口**（`dataApi` 指向的业务统计） | 业务 | 查业务表，属业务逻辑 |
| Schema 页面**注册** `PageRegistry::register` | 业务 `config/route.php` | 业务对插件扩展点的声明 |
| `.vue` 自定义页面文件 | 业务 `app/custom/pages/*.vue` | 插件只负责读取分发，不存放 |
| CURD 业务控制器（Model + `grid()`） | 业务 `app/controller/api/`、`app/controller/admin/api/` | 继承 `BaseCurdController` |
| CURD 路由注册 `RouteControllerRegistry::registerMany` | 业务 `config/route.php` | |
| 菜单 / 权限数据 | 数据库 `menus` / `casbin_rule` | 在后台「菜单管理」维护 |

**页面访问入口约定**（菜单的 `path` 就填它）：

- **CURD 页**：`/mobile-recharge-orders` 这类，即 `registerMany` 的 key；
- **Schema / `.vue` 自定义页**：`/custom-page/<页面名>`（前端 catch-all 路由命中）。

## 5. 环境与兼容

| 项 | 要求 |
|---|---|
| PHP | ≥ 8.1 |
| 框架 | webman（`workerman/webman-framework` ^2.1，官方骨架即可） |
| 数据库 | MySQL —— **单库架构**：认证表与业务表放同一个库，无分库配置项 |
| 依赖 | `composer require` 自动拉齐 `webman/database` `webman/redis` `casbin/casbin` `vlucas/phpdotenv` `webman/captcha`，无需手动装 |
| PHP 扩展 | 登录图形验证码需要 `ext-gd` + `ext-mbstring`；不需要可在配置里 `'captcha_enabled' => false` |

宿主 `composer.json` 需带 webman 官方插件三件套（官方骨架自带，缺失则补）：

```json
"scripts": {
  "post-package-install":  ["support\\Plugin::install"],
  "post-package-update":   ["support\\Plugin::install"],
  "pre-package-uninstall": ["support\\Plugin::uninstall"]
}
```

并确认存在 `support/Plugin.php`（官方骨架文件）。

## 7. 三条必须记住的约定

1. **配置只有一个入口**：宿主根 `config/curd-admin.php`。旧的 `config/curd.php` /
   `config/admin.php` **已不再读取**（2026-09-19 合并），文件存在也不生效 ——
   「改了配置没反应」第一件事就是确认改对了文件。
2. **webman 是常驻内存**：改 PHP 代码或配置后必须 `restart`（或 `SIGUSR1` 平滑 reload），
   热改文件不生效（前端产物同理，改完要重新构建再部署）。
3. **单库架构**：`mysql`（认证）与 `mysql_business`（业务）两个连接**指向同一个库**，
   业务想分库才需要动 `config/database.php`。

## 8. 维护与发布这个文档站

文档源就是本目录的 `*.md`，位置即编号（`00-` 在最前）。改完重跑构建脚本即可：

```bash
cd docs
node tools/build_docs.cjs        # 重新生成 docs/index.html（自包含单页，双击可开）
```

- 站点左侧栏目按**文件名排序**，所以新增文档请沿用 `NN-主题.md` 命名；
- 每篇的第一个 H1 是文档标题，H2/H3 自动生成嵌套目录树；
- 文档之间互相引用请用标准 Markdown 链接 `[标题](NN-主题.md)`：
  在 GitHub 上是可点的文件链接，在文档站里会被自动接管为**页内跳转**（切到对应面板）。

**三种分发方式**：

| 方式 | 说明 |
|---|---|
| 本地 / 离线 | 直接双击 `docs/index.html`，零依赖、无需服务器 |
| 随发布包 | `scripts/release-zip.sh` 已把 `docs/` 与 `INSTALL.md` 打进 zip（排除 `_legacy/`） |
| 在线站点 | 仓库 → Actions → **docs-pages** → Run workflow，把 `docs/` 发到 GitHub Pages（需先在 Settings → Pages 把 Source 设为 "GitHub Actions"；私有仓库需 Pro/Team/Enterprise 才允许 Pages） |

> 放在这里的 `.nojekyll` 是给 GitHub Pages 用的，避免下划线开头的目录被 Jekyll 忽略。
