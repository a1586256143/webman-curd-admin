# 接口加密与异常兜底

两件「线上必备」的事：**接口加密**（防明文抓包 / 篡改，**默认开启**）与**未捕获异常统一兜底**
（防堆栈泄漏，同时给用户一个可报障的编号）。

---

## 1. 接口加密（RSA + AES 信封）

一句话：**默认就是开的，装完即用，你不用做任何事**。要调整只有三件事——
**怎么开**、**怎么关**、**怎么生成 / 更换密钥**。

### 1.1 怎么开（默认已开）

加密开关在**后端**，前端产物自带能力、不需要你重新打包。

| 位置 | 写法 | 优先级 |
|---|---|---|
| `config/curd-admin.php` | `'api_encrypt' => true,` | **最高** |
| `.env` | `API_ENCRYPT=true` | 次之 |
| 都不写 | 视为 `true` | 默认 |

改完 `restart` 生效（webman 常驻内存，改配置不热生效）。

中间件是**插件自带**的（`plugin/curd/config/middleware.php`，键名 `'plugin.curd'`），
覆盖插件全部 `/api/*` 路由，**宿主 `config/middleware.php` 不需要动**。
只有你自己写的、控制器不在 `plugin\curd\...` 命名空间下的接口，才需要宿主再挂一次
（见 [安装指南 §6.1](01-安装指南.md)）。

### 1.2 怎么关

显式关掉即可，二选一：

```php
// config/curd-admin.php
return [
    'api_encrypt' => false,   // 关掉接口加密，走明文
];
```

```dotenv
# .env
API_ENCRYPT=false
```

关掉后：后端中间件完全透传，**前端会自动跟着退回明文**（运行时从后端拿到的开关就是关的），
**不需要重新打包、不需要改任何前端文件**。改完 `restart`。

> 什么时候需要关：接入的第三方客户端不支持加密、或本地用 Postman 之类的工具裸调接口
> 时觉得麻烦。除此之外建议保持开启。

### 1.3 怎么生成 / 更换密钥

密钥是一对 RSA 公私钥，放在 `plugin/curd/config/keys/`：

```
api_rsa_private.pem   0600  私钥 —— 永不外发，务必单独备份，勿提交 git
api_rsa_public.pem    0644  公钥 —— 可公开
```

**装的时候会自动生成**：`composer require amcolin/webman-curd-admin` 结束时会自动跑一次
密钥生成（等价于执行 `php plugin/curd/keygen.php`），**不需要你手动操作**。
Web 安装向导、`php plugin/curd/install.php` 也会生成。

需要手动处理的三种情况：

```bash
# ① 看状态（公钥指纹、开关状态、密钥路径），不生成
php webman curd:crypto-key --show

# ② 生成（已存在则跳过；只有私钥时只补公钥，私钥不动）
php webman curd:crypto-key

# ③ 换一对新的（旧密文将无法解密；换完 restart）
php webman curd:crypto-key --force
```

没装 webman console 时用**独立脚本**（纯 openssl，不依赖框架）：

```bash
php plugin/curd/keygen.php            # 生成
php plugin/curd/keygen.php --show     # 只看状态与指纹
php plugin/curd/keygen.php --force    # 换一对新的
```

> **换密钥后不用重新打包前端**：前端启动时向本机后端要公钥（`GET /api/config/crypto`），
> 拿到新公钥后自动重签，前端会自己重新握手。
> 但**必须 `restart`**（或平滑 reload）—— 私钥在进程内存里，不重启就还是旧的。

安装时想跳过生成：`CURD_SKIP_KEYGEN=1 composer require amcolin/webman-curd-admin`。

### 1.4 怎么确认加密生效

浏览器 DevTools → Network → 点任一 `/api` 请求：

| 看什么 | 结论 |
|---|---|
| Request 里是 `ENC1:...` | 请求已加密 |
| Response Headers 有 `X-Crypto-Encrypted: 1` | 响应已加密（前端会自动解密，页面照常显示数据） |
| 两个都没有 | 这一路走的是明文 |

命令行自查：

```bash
curl -s http://127.0.0.1:8787/api/config/crypto
# {"code":200,"data":{"enabled":true,"handshake":true,"public_key":"-----BEGIN PUBLIC KEY-----\n...","fingerprint":"f646e10936ace1ff"}}
```

- `enabled: false` → 后端关了加密（`api_encrypt=false` / `API_ENCRYPT=false`）；
- `public_key` 为空 → 密钥没生成，跑一次 `php plugin/curd/keygen.php`；
- `fingerprint` 与 `php webman curd:crypto-key --show` 的指纹不一致 → 进程还在用旧私钥，`restart`。

### 1.5 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 请求加密了，响应却是明文 | 加密是对称的：响应只能用**本次请求带来的**密钥加密。请求本身是明文时，响应必然明文 —— 先确认请求带了信封 |
| 全部请求 400「请求解密失败」 | 前端手里的公钥与后端私钥不配对（换过密钥没 restart）。后端会回 `X-Crypto-Key-Mismatch`，前端会自动重新握手重试一次；仍不行就 `restart` |
| 换了密钥后老数据解不开 | 正常：私钥换了，旧密文就废了。历史数据要保留请**备份旧私钥** |
| 抓包看到 `ENC1:...` | 正常，这就是加密生效的样子 |
| 关闭加密后前端报错 | 后端 `restart` 了吗？前端拿到的是运行时开关，不重启还是旧状态 |

> 加密的定位是「防明文抓包 / 防篡改」，不是「防前端开发者」——
> 浏览器要执行加密代码，算法本身就藏不住。私钥永远只在后端，前端产物里**不含任何密钥**。

## 2. 接口异常兜底

SQL 报错、类型错误等**未捕获异常**的统一出口，由插件自带的
`plugin\curd\app\exception\CurdExceptionHandler` 负责。

### 2.1 生效范围

| 范围 | 怎么生效 |
|---|---|
| **插件路由**（`/api/auth/*`、`/api/curd/*`、`/api/admin/*`、`/api/menu/*` …） | **开箱生效**：插件自带 `plugin/curd/config/exception.php` |
| **宿主自己的 `/api` 控制器** | 把宿主 `config/exception.php` 的 `''` 键指向插件处理器（见下） |

```php
// config/exception.php
return [
    '' => \plugin\curd\app\exception\CurdExceptionHandler::class,
];
```

> ⚠️ 只加 `'@'` 键**无效** —— 框架规则是「本 app 配置里已有 `''` 键 ⇒ 忽略 `'@'`」，
> 而 webman 骨架默认自带 `'' => support\exception\Handler::class`。

只兜 `/api`；非 `/api` 请求任何模式下都沿用框架默认错误页 / 调试页。

### 2.2 两档模式

由 `.env` 的 `APP_DEBUG` 决定：

| 模式 | 行为 |
|---|---|
| `true`（默认，**本地**） | 异常信息**原样暴露**：JSON 请求返回真实 msg + traces，其余返回调试页 —— 当场可查 |
| `false`（**线上**） | `/api` 返回 **HTTP 500** `{"code":500,"msg":"服务内部错误（编号 xxxxxxxx）"}`；异常类 / 消息 / **SQL + 绑定** / 请求上下文 / 堆栈写 `runtime/logs/webman.log` |

- 宿主自己控制器的模式取宿主 `config/app.php` 的 `debug`，与插件 debug **取交集**（任一为 `false` 即按线上处理）；
- 响应刻意用 **HTTP 500** 而非 200：便于 Nginx / 监控按 5xx 告警；
- 提示文案可改：`config/curd-admin.php` 的 `error_message`。

### 2.3 拿到编号就等于拿到线索

```
服务内部错误（编号 a1b2c3d4）
```

```bash
grep a1b2c3d4 runtime/logs/webman.log
```

即可看到异常类、消息、SQL 与绑定。日志刻意做成「一条异常一行」（堆栈换行收敛成 ` | `，
关键字段排在堆栈之前），可以放心用 `grep` / `jq` / 采集器解析。
