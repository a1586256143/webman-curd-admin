# 升级 · 部署 · 发布

升级为什么不会自动生效、怎么把新版插件同步进宿主、上线部署要配什么、怎么打发布包。

---

## 1. 升级安全（避免本地改动被静默覆盖）

安装器策略：**`plugin/curd` 已存在就跳过拷贝**（保护本地改动）。因此
`composer update amcolin/webman-curd-admin` 只会更新 `vendor/` 里的包，
**不会动**宿主 `plugin/curd` 与 `config/` 下的文件。

要把新版插件文件同步到宿主，走这两步：

```bash
# ① 升级前先检查宿主 plugin/curd 有无本地改动（0=无改动，1=发现改动）
./scripts/check-plugin-overrides.sh <宿主项目根>

# ② 确认无本地改动（或已备份）后整体重拷
bash scripts/sync-plugin.sh
#    = 备份 plugin/curd → plugin/curd.bak-<时间戳>，再从 vendor 整体重拷
#    宿主 config/curd-admin.php 与 config/database.php 已存在，不会被覆盖
```

发现改动时：先 `git stash` / 提交 / 把改动**迁回插件配置化**，再升级。

> 只改了内置前端的话，用 `scripts/build-frontend.sh` 重建 dist 即可，
> 不必动 `plugin/curd` 源码。

**升级后建议再跑一次幂等安装**，补齐新表 / 新种子 / 新菜单：

```bash
php plugin/curd/install.php      # 幂等：已存在的全 SKIP
php plugin/curd/migrate.php      # 如有增量迁移文件
```

## 2. 同步清单：哪些文件属于宿主、不能覆盖

`sync-plugin.sh` 会整体重拷 `plugin/curd`，但下列内容属于**宿主专有**，
绝不能覆盖或删除（手工同步时逐条核对）：

| 文件 / 目录 | 说明 |
|---|---|
| `plugin/curd/config/keys/` | RSA 私钥（`.gitignore` 排除，换机需手动拷贝，丢失要重生成） |
| `plugin/curd/install-business.sql` | 宿主真实业务建表 SQL（`--business-sql` 用它） |
| `plugin/curd/public/assets/` | 宿主自己的前端构建产物（若是自行构建的版本） |
| `plugin/curd/migrations/` | 宿主的增量迁移文件（`V{n}__*.sql`）—— 同步时不要删除 / 覆盖 |
| 宿主根 `config/curd-admin.php`、`config/database.php`、`.env`、`app/` | 插件之外的宿主自有层 |

顺带一提，包 → 宿主需要同步的核心条目是：`api/Install.php`、`app/`、
`config/*.php`、`env.example`、`install.php`、`install.sql`、`migrate.php`、`public/`。

## 3. 卸载

```bash
composer remove amcolin/webman-curd-admin
# 卸载钩子不自动删目录（避免误删本地开发版），手动清理：
rm -rf plugin/curd
php start.php restart
```

数据库表与 `config/curd-admin.php` 需自行决定是否清理。

## 4. 生产部署

### 4.1 守护进程（supervisor）

```ini
# /etc/supervisor/conf.d/my-app.conf
[program:my-app]
command=php /var/www/my-app/start.php start
directory=/var/www/my-app
numprocs=1
autostart=true
autorestart=true
startretries=3
user=www-data
redirect_stderr=true
stdout_logfile=/var/log/my-app/worker.log
```

```bash
supervisorctl reread && supervisorctl update && supervisorctl start my-app
```

> 不要裸跑 `php start.php start -d`。托管后整体重启用 `supervisorctl restart my-app`
> （手动 `php start.php restart` 会杀会话进程组）。插件的 `SIGUSR1` 平滑 reload 只重启
> worker、不杀 master，与 supervisor 托管兼容，仍可用于「改配置即时生效」。

### 4.2 Nginx 反代（SPA 与 API 同域，免 CORS）

```nginx
server {
    listen 80;
    server_name admin.example.com;
    root /var/www/my-app/public;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }
    location /index.php {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root/index.php;
        fastcgi_pass 127.0.0.1:8787;   # 与 config/process.php 的 'listen' 一致
    }
    location /app/curd/ {              # 插件内置前端（SPA history 由 PageController 处理）
        try_files $uri $uri/ /index.php?$query_string;
    }
}
```

webman 侧取真实客户端 IP 用 `connection->getRemoteIp()`，依赖 Nginx 正确透传。

### 4.3 环境与密钥（上线检查单）

- [ ] **`.env` 设 `APP_DEBUG=false`** —— 否则接口未捕获异常会把堆栈 / 表结构直接抛给前端，
      既泄漏实现细节、又拿不到统一提示；
- [ ] **`config/exception.php` 的 `''` 键**指向
      `\plugin\curd\app\exception\CurdExceptionHandler::class`（宿主自己的 `/api` 控制器才覆盖到；
      插件路由靠插件自带配置已生效）；
- [ ] **`config/middleware.php` 的 `'@'` 组**注册 `StaticFile` + `ApiCrypto`
      （加密关闭也保留，否则前端加密请求无人解）；
- [ ] `config/curd-admin.php` 开 `admin_require_permission => true`；
- [ ] 登录后立即修改初始管理员密码；
- [ ] `config/keys/` 独立挂载、不进 git / 不进发布产物；
- [ ] 开发 / 测试 / 生产各用独立数据库，`.env` 不进 git。

细节见 [接口加密与异常兜底](07-接口加密与异常兜底.md) 与 [配置参考](02-配置参考.md)。

### 4.4 备份

| 对象 | 频率 | 方式 |
|---|---|---|
| 数据库（认证表 + 业务表同库） | 每日 | `mysqldump` 全量 + 保留 7 天 |
| `config/keys/`（RSA 私钥） | **生成即备份** | 单独加密归档，切勿丢失 |
| 代码 / 前端 dist | 每次发版 | git tag + CI 产物 |

> RSA 私钥丢失不影响登录，只影响已加密的接口。

### 4.5 升级与回滚

```bash
# 升级前确认无本地改动
./scripts/check-plugin-overrides.sh <宿主项目根>
bash scripts/sync-plugin.sh          # 自带备份 plugin/curd.bak-<时间戳>
php plugin/curd/install.php          # 幂等补表 / 补种子 / 补菜单
```

回滚 = 恢复 `plugin/curd.bak-*` 后 reload；或 `git checkout <上一版本 tag>` /
composer 锁版本重装。

## 5. 发布（zip / GitHub Release）

```bash
# 本地打 zip（排除 keys / install-business.sql / release-zip.sh 自身）
./scripts/release-zip.sh 1.1.0
# → dist/webman-curd-admin-v1.1.0.zip（约 1.1M，解压即用）

# 发布到 GitHub
git tag v1.1.0 && git push origin v1.1.0
# → .github/workflows/release.yml 自动跑：
#   composer validate --strict → 全量 php -l → 前端 dist 完整性校验
#   → 关键文件存在性校验 → release-zip.sh → GitHub Release 附 zip
```

> **CI 不跑 npm**：内置前端由开发者本地 `scripts/build-frontend.sh` 构建后提交 dist，
> CI 只校验产物完整性（`index.html` + `assets/` + 文件数 > 10）。
>
> zip 包内容 = `composer.json` + `README.md` + `INSTALL.md` + `docs/` +
> `plugin/curd/` + `scripts/`；`config/keys/`、`install-business.sql` 不进包。

## 6. 与本项目 webman-huafei-platform 的关系

本包由 `webman-huafei-platform/plugin/curd` 发布而来，演进分三阶段：

| 阶段 | 做了什么 |
|---|---|
| **M1** 自包含下沉 | middleware / rbac / model / helpers / `casbin.conf` 全部内置，插件不再依赖宿主 `app\middleware`、`app\rbac`、`app\functions.php`、`app\model\CurdConfigs`；宿主业务代码零改动、行为不变 |
| **M2** 开箱即用 | `install.sql` + `api/Install.php` + `install.php` 一键建表 / 种子 / 密钥；前端 dist 内置 `public/`，`/app/curd/` 直接打开完整后台 |
| **M3** 管理面内置 | 用户 / 角色 / 个人中心下沉进插件并注册路由（宿主同名路由优先，零行为变化）；新增 `admin_require_permission` 收紧开关；路由注册改走 `curd_route()` 冲突检测（修掉「重复注册抛 Route conflict」的崩溃点）；在全新空 webman 项目上完成端到端验证 |

**M5 宿主旧副本下线**：宿主侧的 `app/middleware/*`、`app/rbac/*`、`app/functions.php`
已切到插件内置版并删除（`StaticFile.php` 是宿主自有，保留）。

> 宿主开发期两条命令：
> `scripts/release.sh` 把宿主侧改动回灌到包；`scripts/build-frontend.sh` 重建内置前端。
