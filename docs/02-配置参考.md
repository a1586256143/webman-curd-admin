# 配置参考

全部可调点、默认值与覆盖规则。**改完必须重启 webman**（配置在启动期读取）。

---

## 1. 配置从哪读、谁能覆盖谁

插件以「**根目录应用插件**」形式分发（`{项目}/plugin/curd`），而 webman 的配置加载顺序是
`config/` 先、`plugin/*/config` 后 —— 也就是说**插件自带的配置会覆盖
`config/plugin/curd/curd.php`**。所以调参不能写在 `config/plugin/curd/` 里。

| 优先级（高 → 低） | 位置 | 说明 |
|---|---|---|
| 1 | 宿主根 `config/curd-admin.php` | **唯一推荐入口**，`composer require` / Web 向导自动生成模板 |
| 2 | `plugin/curd/config/curd.php` 的 `$defaults` | 插件内置默认，随包升级整体替换，**不要改这里** |

合并逻辑（`plugin/curd/config/curd.php` 末尾）：宿主文件存在就
`array_merge($defaults, $hostCurd)` —— **同名顶层键被宿主覆盖，没写的键保持默认**。

> ⚠️ **旧的 `config/curd.php` 与 `config/admin.php` 已不再读取**（2026-09-19 合并为一个文件）。
> 这两个文件即使存在也不生效。排查「配置改了没反应」时，先确认改的是不是
> `config/curd-admin.php`，再确认有没有 `restart`。

插件内部读取分两类：

| 键的类型 | 读取方式 | 举例 |
|---|---|---|
| **插件调参键** | 合并进 `config('plugin.curd.curd.*')` | `page_base`、`admin_require_permission`、`auth_state_guard` |
| **宿主管家键** | 直接读 `config('curd-admin.*')` | `site`、`home_page`、`upload_path`、`captcha_*` |

## 2. 数据库连接

**数据库信息只写在宿主 `.env` 的 5 个键**，由 `config/database.php` 用 `env()` 读取：

```bash
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=webman_curd
DB_USER=root
DB_PASSWORD=your_password
```

- **单库架构**：认证表（`admin_users` / `admin_tokens` / `roles` / `admin_role_user` /
  `role_permission` / `casbin_rule` / `curd_configs` / `menus`）与业务表放**同一个库**，
  已无 `DB_BUSINESS_NAME`、无「分库选项 / 同库勾选」。
- `mysql_business` 连接**仍然保留**（兼容已写死 `$connection = 'mysql_business'` 的模型），
  其 `database` 与 `mysql` 相同（= `DB_NAME`），两个连接指向同一库，零额外开销。
- `.env` 不进 git。Web 安装向导写 `.env` 时是**按键合并**，不会动其它键。

### 想真正分库 / 想去掉 mysql_business

| 目标 | 做法 |
|---|---|
| 分库 | 在 `config/curd-admin.php` 的 `database.business_db` 填不同库名，然后重装向导或手动改 `config/database.php`；`.env` 保留 `DB_BUSINESS_NAME` 即可（插件只认 `admin_connection` / `business_connection` 两个**连接名**，两个连接都定义着就不冲突） |
| 切回单库 | 去掉 `.env` 的 `DB_BUSINESS_NAME`，把 `config/database.php` 里 `mysql_business.database` 改成 `env('DB_NAME')` |
| 不要这个连接 | 在 `config/database.php` 删掉 `'mysql_business' => [...]` 整块；业务代码里出现 `Db::connection('mysql_business')` 的改成 `mysql`，或在每个模型里 `protected $connection = 'mysql';` |

## 3. 插件调参键（全量）

默认值取自 `plugin/curd/config/curd.php` 的 `$defaults`；在宿主 `config/curd-admin.php`
写**同名顶层键**即可覆盖。

| 配置键 | 默认值 | 说明 |
|---|---|---|
| `admin_connection` | `mysql` | 认证 / 菜单 / RBAC 库**连接名**（认证表所在库） |
| `business_connection` | `mysql_business` | 业务模型 CURD 默认连接名（单库下与 `mysql` 同库） |
| `model_dir` | `{根}/app/model` | 宿主业务模型扫描目录（自动登记进 `ModelRegistry`） |
| `model_namespace` | `app\model` | 模型命名空间 |
| `controller_dirs` | `app/controller/api` + `app/controller/admin/api` | CURD 业务控制器扫描目录（继承 `BaseCurdController` 会自动关联模型） |
| `vue_pages_dir` | `{根}/app/custom/pages` | 宿主业务 `.vue` 页面目录（`CustomPageController` 读取分发） |
| `casbin_model_path` | 插件自带 `config/casbin.conf` | casbin 模型文件 |
| `base_model_class` | `plugin\curd\app\model\BaseModel` | 运行时动态生成模型的基类；宿主有增强版可改回 `app\model\BaseModel` |
| `allow_unresolved` | `true` | 推导不出权限标识的路径：`true` = 仅登录放行 / `false` = 403 |
| `export_max_rows` | `100000` | 单次导出最大行数（`<= 0` 不限制）；超限返回 `{"code":400,"msg":"本次将导出 N 条，超过单次导出上限 M 条..."}`，前端当错误提示而非下载 |
| `error_message` | `服务内部错误` | 线上异常兜底的提示文案（编号自动追加） |
| `home_page` | `/dashboard` | **默认落地页**（登录成功后、以及访问后台根路径 / 刷新时打开哪一页）；详见 [菜单与权限](05-菜单与权限.md) |
| `captcha_enabled` | `true` | 登录页是否显示图形验证码（关掉即前端不渲染、后端也不校验） |
| `captcha_ttl` | `300` | 验证码有效期（秒） |
| `captcha_length` | `4` | 验证码位数（3~6，越界回落 4；字符集已剔除易混的 `i l o 0 1`） |
| `admin_require_permission` | `false` | `/api/admin/*` 是否强制 RBAC 校验；**生产建议 `true`**（admin 角色有 `p,admin,*,*` 不受影响） |
| `auth_provider` | `DefaultAuthProvider` | 登录提供方（可插拔，实现 `AuthProviderInterface`）；详见 [认证与登录](06-认证与登录.md) |
| `auth_state_guard` | `''`（不启用） | 账号状态钩子（实现 `AuthStateGuardInterface`），在账号自身 `status` 之外叠加业务判定 |
| `login_handler` | `''`（用内置） | 接管整个 `/api/auth/login` 的类名 |
| `permission_enabled` | `true` | 权限总开关：`false` = 全部放行，且不生成 / 不下发任何权限 |
| `page_base` | `/app/curd` | 内置前端 URL 前缀（改需同步用同 `VITE_BASE_PATH` 重建前端） |
| `public_dir` | `plugin/curd/public` | 内置前端产物目录 |

## 4. 宿主管家键

这些键**直接读 `config('curd-admin.*')`**（不走 `plugin.curd.curd.*`），同样写在
`config/curd-admin.php`。

### 4.1 站点信息 `site`

前端 `/api/config/site` 读取，用于侧边栏 logo、登录页、浏览器标签：

```php
'site' => [
    'title'     => '话费充值系统',             // 站点标题（logo 文字 / 登录页 / 浏览器标签）
    'logo'      => 'Monitor',                 // logo_type=icon 时为 el-icon 组件名；=image 时为图片 URL
    'logo_type' => 'icon',                    // icon | image
    'copyright' => '© 2022-2026 话费充值系统', // 页脚版权
    'favicon'   => '',                        // 浏览器标签图标 URL（空 = 用默认 favicon）
],
```

### 4.2 默认落地页 `home_page`

```php
'home_page' => '/custom-page/home',   // 写「不含部署前缀」的相对路径
// '/dashboard' → 内置首页（插件默认值）
// 也可写完整 URL（http://...），前端整页跳转
```

优先级：`home_page` → `site.home_page` → 插件默认 `/dashboard`。
改完**即生效**（前端每次启动都拉 `/api/config/site`），**无需重建前端**。
只决定「打开哪一页」，不校验用户有没有该页面的菜单 / 权限。

### 4.3 上传与静态资源

| 键 | 示例 | 说明 |
|---|---|---|
| `upload_path` | `uploads` | 上传目录（相对 `public`）；`local` 驱动存本机 `public/<upload_path>` |
| `upload_driver` | `local` | 存储驱动 |
| `image_server` | `http://127.0.0.1:8787/` | 图片 / 静态资源前缀，DSL 列与表单的 `staticHost` 拼装用它，可被 `->staticHost('...')` 单独覆盖 |

### 4.4 导出与验证码

```php
'export_max_rows' => 100000,   // 0 = 不限制；调小可防「全表导出」拖垮服务（同步查询 + 内存拼 CSV）
'captcha_enabled' => true,     // false = 登录页完全不显示验证码，登录接口也不再校验
'captcha_ttl'     => 300,      // 有效期（秒）
'captcha_length'  => 4,        // 位数 3~6
```

> 验证码明文存 **Redis**（key `curd_captcha:{随机串}`，一次性，校验后即删）。
> **Redis 挂了就没人能登录** —— 应急把它设为 `false` 并重启即可放行。

## 5. 路由「宿主优先」机制

webman 的 `Route` 对「同 method + 同 path」重复注册会**直接抛异常**（`Route conflict`）。
插件因此统一用 `curd_route()` 注册路由：注册前检测该路径是否已被注册，**已注册则跳过，
保留宿主实现**。

- 路由加载顺序：宿主 `config/route.php` → `plugin/{name}/config/route.php`；
- **存量项目**（自己注册过 `/api/admin/*`、`/api/config/site` 等）：装插件不冲突、行为不变，
  继续走宿主控制器；
- **新项目**：无同名路由，插件路由全部生效 —— `/api/auth/*`、`/api/admin/*`、`/api/menu/*`、
  `/api/curd/*`、`/api/custom/*`、`/api/options/*`、`/api/upload`、`/app/curd/*`。

## 6. 内置前端与 `page_base`

内置前端（Vue3 + Element Plus）的 dist 已放进 `plugin/curd/public/`，由
`plugin/curd/app/controller/PageController.php` 承载：

- `/app/curd/*` 下真实存在的文件按静态资源返回；
- 其余路径（vue-router history 路由，如 `/app/curd/dashboard`）回退 `index.html`；
- `PageController` 做了**路径穿越防护**。

改前缀：`config/curd-admin.php` 的 `page_base`（默认 `/app/curd`），
**必须用相同的 `VITE_BASE_PATH` 重新构建前端**：

```bash
VITE_BASE_PATH=/your-prefix VITE_API_BASE_URL= VITE_API_ENCRYPT=false npm run build
```

存量 OSS / CDN 部署不受影响：不设 `VITE_BASE_PATH` 时 vite base 与旧版一致（`/` 或 OSS URL）。

## 7. 环境变量一览

| 变量 | 用途 |
|---|---|
| `DB_HOST` `DB_PORT` `DB_NAME` `DB_USER` `DB_PASSWORD` | 数据库连接（**唯一必填组**） |
| `APP_DEBUG` | 决定 `/api` 异常兜底走「本地暴露」还是「线上 500 + 编号」 |
| `API_ENCRYPT` | 后端接口解密开关，**默认 `true`**，`.env` 设 `false` 才关（详见 [接口加密与异常兜底](07-接口加密与异常兜底.md)） |

> ❌ **`CURD_*` 环境变量已全部移除**。历史上的 `CURD_ADMIN_CONNECTION` /
> `CURD_BUSINESS_CONNECTION` / `CURD_ADMIN_REQUIRE_PERMISSION` 等已不再读取 ——
> 插件调参统一收敛到宿主 `config/curd-admin.php`。
>
> 前端构建期变量（`VITE_BASE_PATH` / `VITE_API_BASE_URL` / `VITE_API_ENCRYPT` /
> `VITE_API_RSA_PUBLIC_KEY`）不是运行期配置，只在 `npm run build` 时内联。
> 完整键清单见 `plugin/curd/env.example`（**参考用，勿整文件覆盖宿主 `.env`**）。
